## 开篇公式
1. **强钩子先出**：发布/争议/演示/惊人结论（「正式发布」「这显然有点夹带私货」「主线程阻塞时…」）
2. **权威与来源立刻钉上**：人名+机构+角色（Anthropic 工程师 Kevin Bai；ChatGPT 联合发明人；Thariq 说…）
3. **关键术语直给**：FDE / System One / MCP / SwiftUI… 并马上用人话解释一句
4. **硬数字跟上**：ACV、延迟、倍数、代码行数、token、百分比

## 正文结构
- 短段推进；长帖用显式小节 / 第一第二第三 / 场景清单
- 先讲清「是什么 / 解决什么」，再对比框架（FDE vs 外包；MCP vs CLI；SwiftUI vs UIKit）
- **先承认对立面再下判断**（trade-off，不单边吹）
- 续帖可以极短：「补充一个很好的点」「给视频加个字幕」「回应贴：」

## 结尾
- 落到可执行：谁该用、什么时候选 A 不选 B、API/模型名（小红书文案里不放链接，只写名称）
- 少鸡汤、少「带走清单」制作腔

## 落到小红书五图
- 封面大字 = 权威 + 术语（+ 数字）；红字继续术语/数字，禁止「带走××」
- 文案前 2 行复刻开篇公式
- 内页用追问/对比小节；可带走清单放内页与正文
