# 文章 → 小红书图文（elsewhere 文风）

用户给一篇文章或一段内容，产出一套小红书图文：卡片图、标题、正文、置顶评论。

分工如下：
- **文字**按 elsewhere 文风写，细则在 `references/elsewhere_voice.md`，动笔前必须先读完。
- **版式和 IP** 完全沿用 Krypto说AI 现有的图文格式。
- **平台规则**沿用 youtube-xhs。

## 先定位目录（每次开始都做）

- `$A` = 本 SKILL.md 所在目录。
- `$X` = 同级的 `xiaohongshu-wutu-zhishika`，出图脚本和头像都在里面。
- `$Y` = 同级的 `youtube-xhs`，里面有 `check_paste.py`、`post_log.py`，还有「封面、标题、文案硬规则」。
- 同级目录里找不到时，执行 `find / -type d -name <目录名> 2>/dev/null | head -1`。
- 本地（Mac）的输出目录是 `~/Documents/Krypto说AI/<YYYY-MM-DD>_<英文短标题>/图文版/`。云端（claude.ai / Cowork 沙箱）输出到当前环境能下载给用户的位置，比如 `/mnt/user-data/outputs/`。

```
<日期>_<短标题>/图文版/
  01.png … NN.png   overview.jpg
  标题.txt  标题备选.txt  正文.txt  置顶评论.txt
  封面备选/          三版封面（A 认知冲突 / B 好奇缺口 / C 数字锚定）
  领取物/            本期可领取物
  编辑用/ cards.json  covers.json  avatar.png  source.md（原文存档）
```

## 步骤

### 0. 拿到原文
- 用户粘贴的文本或上传的文件：原样存到 `编辑用/source.md`，开头写上作者、媒体、标题、发布日期。
- 用户只给了链接：先试着抓正文。抓不到（公众号常见）就请用户粘贴全文，**不要凭标题脑补内容**。
- 发布日期不明时，问一句，或者在 source.md 里标「日期未知」。文中的「最近、今年」要按原文的发布时点理解。

### 1. 读原文，定文体和口味
读 `references/elsewhere_voice.md`，然后通读原文，列出下面这些：
- **文体**：交易内幕 / 人物特稿 / 访谈 / 行业评论 / 清单盘点 / 观点，对应手册第 4 节的骨架。
- **作者口味**：从手册第 7 节挑一种为主，比如争议题材用吴睿睿式的调查锋芒，人物题材用陈之琰式的温暖叙事。
- **素材清单**：
  - 一个最强的钩子（新闻、场景、悖论、统计梗）；
  - 「为什么现在」；
  - 全文要回答的一个问题；
  - 3 到 5 个故事或论点；
  - 所有硬数字；
  - 两三个物件或动作细节；
  - 两三句最有反差的原话；
  - 能回扣开头的意象。
- **信源**：原文里的信源怎么表述，就照原样记下来，比如「接近交易的人」「一位投资人」。后面转述时只能用原文里有的信源。

### 2. 要立场（和 youtube-xhs 一样）
把 3 个最可争论的点列给用户，问一句「你站哪边」。「我的看法」页、正文第一屏、A/B 问题都围绕这句立场写，而且立场要写成**可以被反对的判断**。用户说「你定」时自己选一个，交付时标注「立场是我替你选的」。

### 3. 栏目与期数
- 默认栏目名是「**长文精读 #N**」，写在封面眉标和正文第一行。期数取 `~/Documents/Krypto说AI/log.csv` 里同栏目的最大期数 +1。
- 第一次使用、log 里没有这个栏目时，先问用户栏目叫什么、从第几期开始，名片卡上的定位句也一并确认。默认定位句是「每周精读 2 篇好文章」。
- 不要用「海外精读」，那是 youtube-xhs 的栏目，除非用户明说要并进去。

### 4. 写 cards.json（文字是 elsewhere，版式是 Krypto说AI）
先把 `$X/assets/avatar.png` 复制到 `编辑用/`。`account` 固定写 `{"name": "Krypto说AI", "avatar_image": "avatar.png", "date": "<今天 MM/DD>"}`。

一共 6 到 8 页，页序固定：

| 页 | 字段 | 写法 |
|---|---|---|
| 1 封面 | `"cover": true`、`tag`、`title`，可选 `evidence` | `tag` 写「长文精读 #N · 作者 / 媒体」。`title` 是一句 10 到 12 字的结论大字，用 `<br>` 断成两行，**每行 5 到 6 字**（每行只有 4 字时会碰到字号上限，撑不满 80% 宽）。写成 elsewhere 的套路：化用、反差、悖论、「不是 X，是 Y」。有人物照片（用户提供）时放 `evidence`。导语、小字、图表不上封面 |
| 2 开场页 | `title`、`blocks` | 页标题用手册第 1 节的主标题套路，可以比封面长。blocks 依次写：钩子一句，单独一段；「为什么现在」一段；抛出问题一段；最后「以下是……的故事」。这是手册第 3 节的五步开头 |
| 3 到 N-2 叙事页（3 到 5 页） | `title`、`blocks`，可选 `table` / `evidence` | 页标题整套只用手册第 2 节里的**同一种**小标题套路。每页一个小故事或论点，2 到 3 段短文，用上精确数字、物件、原话，信源照原文转述。**每页最后一段是一句 `==短评==`**，比如「==难的是中间的钱。==」，不超过 20 字。数字多时用 `table`。最后一张叙事页的结尾用人物的一句话，或回扣开头的意象 |
| N-1 我的看法 | `title`、`blocks` | 页标题就是那句可以被反对的判断，可以用 elsewhere 式的反问。blocks 写一段理由，然后 `hr`，最后一段二选一问题「==你是 A 还是 B？==」，和正文里的 A/B 问题一致 |
| N 名片卡 | `title`、`blocks` | `title` 写「关注看下一期」。blocks 依次写定位句、「下一期：XX」、「评论区扣 1 领本期XX」。每期同一版式，不写「求关注」 |

卡片上的文字规则：
- 纯文字页每页正文 180 到 260 字，填满画面约三分之二：少于 150 字下半页会空一半，多于 280 字会溢出。放不下就拆页，或者删掉次要细节，不要缩字号。有证据图（原文截图、人物照、图表）的页，正文控制在 120 字以内。
- `==…==` 只包一整句判断，一页最多两处。
- 卡片上不放链接、二维码、「公众号」「微信」这类字眼。

示意，页标题的一种写法：

```json
{"title": "十年苦熬<br>一年登仙", "blocks": [
  {"p": "近 20 家美元 VC 里，今年冒出 4 位新管理合伙人。其中两位在机构里待了超过 10 年，职级长期不动。"},
  {"p": "变化来自 AI：从出手到拿结果，这次只用了两三年。"},
  {"p": "==AI 加速了一切，包括熬资历。=="}
]}
```

### 5. 出图、检查
```bash
python3 $X/scripts/render_cards.py 图文版/编辑用/cards.json 图文版/
```
出图后 **Read `overview.jpg`**，逐项检查：
- 封面大字在缩略图上能不能一眼读出（超过 12 字或字宽不到画面 80% 就重写）；
- 有没有溢出或截断；
- 每页的短评是否落在页尾；
- 页标题的套路是否统一。

有问题就改 cards.json 重新出图。云端出图失败时只交付 cards.json，告诉用户回到 Mac 上一句话就能出图。

### 6. 标题与封面各 3 版
- `标题备选.txt` 写三行，用 elsewhere 的三种套路：
  - **A 化用型**：化用名句、书名、台词；
  - **B 反差口语型**：「可能是……」「我去……了，拜拜」；
  - **C 人物引语型**：「人名：一句信条」。
- 每行都要过 youtube-xhs 的「标题五条铁律」：不超过 20 字；前 8 字里有人名、机构或数字；留悬念，不说答案；不用英文开头；不用「干货 / 教你」。化用型要把人名或机构放到前面，例如「王兴兴：即使没人看好，也要造出一只狗来」。
- 你认为最强的一条写进 `标题.txt`，并在对话里说明理由。
- 封面 3 版写进 `编辑用/covers.json`，只含 3 个封面页，其他字段同 cards.json。三版分别用认知冲突、好奇缺口、数字锚定三种触发器，渲染到 `封面备选/`。`01.png` 先用你推荐的那一版。

### 7. 正文.txt 与置顶评论
正文是纯文本，能直接粘贴进小红书，不用任何 Markdown 符号。按下面的顺序写，语气是 elsewhere 的冷静叙事：
1. 第 1 行：「长文精读 #N」。
2. 第 2 行：一句钩子，交代谁、哪篇，例如「这是一个关于 Kimi 最难那一年的融资故事。」
3. 第 3 到 5 行：我的看法，写成可以被反对的判断，用第一人称。
4. 第 6 行：「每周 2 篇，下一期：XX」。
5. 3 个「小故事」：每段两三句，用「1.」「2.」或「·」开头，每段结尾带一句短评。
6. 二选一互动：「你是 A 还是 B，评论区打 A 或 B」。
7. 出处：「来源：作者 · 媒体 ·《原标题》」，不放链接。
8. 标签不超过 8 个：3 个大流量 + 3 到 5 个精准，人名、机构必须在里面。

每篇配一个可领取物（比如时间线表、人物关系图、清单），文件放 `领取物/`。另写 `置顶评论.txt`，一句随手回复的口吻，比如「时间线整理好了，评论区扣 1 我发你」。

### 8. 交付
- 运行 `python3 $Y/scripts/check_paste.py "<输出目录>"`，✗ 全部改到 ✓；⚠ 逐条看。化用型标题前 8 字没有人名的 ⚠，能改就改。
- 自查以下几项：
  - 页标题套路统一；
  - 每张叙事页有短评；
  - 信源没有超出原文；
  - 直接引用不超过两句；
  - 封面大字不超过 12 字；
  - 末页有名片卡和下一期；
  - 正文有 A/B 问题；
  - 有 `置顶评论.txt` 和可领取物。
- 记一行日志：
  ```bash
  python3 $Y/scripts/post_log.py add --dir "<输出目录>" --series 长文精读 --no <N> --topic <文体> --title-type <化用|反差|人物> --title "<标题>"
  ```
- 用 SendUserFile 发出这些文件：`overview.jpg`、`封面备选/overview.jpg`、`标题.txt`、`标题备选.txt`、`正文.txt`、`置顶评论.txt`。
- 汇报内容：文体和口味选择、立场（是否替用户选的）、三个标题各用了哪种套路、推荐哪一条、需要用户补的东西（立场、日期、可领取物）。
- 不自动登录小红书，不代发。

## 反模式
- 把原文逐段缩写成卡片。要先按文体骨架重组，再落到每一页。
- 页标题混用多种套路，比如一页是意象，下一页是问句。
- 短评写成大段议论，或者一页里放多句短评。
- 编造信源、细节、原话；化用一句不存在的名言。
- 自称「elsewhere」，或者用它的栏目名。
- 封面堆导语或多行小字（违反 youtube-xhs 的封面规则）。
