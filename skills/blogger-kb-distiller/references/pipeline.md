# 蒸馏引擎详细模板（平台无关）

本文件是 SKILL.md「五步引擎」的落地细节。所有步骤与平台无关，adapter 已把内容变成统一中间格式。

---

## Step 3 · Classify（分类聚类）Prompt 模板

给 LLM 的输入：`_ingest.json` 的 items（num / title / date / 前若干字 text 摘要）。

> 你是知识架构师。下面是一批某博主的内容条目（编号 / 标题 / 发布日期 / 摘要）。
> 请把它们按主题聚成若干「合成单元」(unit)，规则：
> 1. 每个 unit 聚合 2–15 个主题相近的条目；单条不足以成文的，必须并入相关 unit（跨视频熔合是本流程核心）。
> 2. 给出一级分类（如：境内IPO、港股、投融资文件、股权尽调、交易方案、方法论、行业观察、特殊权利、税务、国企、劳动合规、合同实务、书单阅读、生活随笔…按博主实际主题调整，不必全用）。
> 3. 每个 unit 输出：{id(1起), name(单元主题名), files:[相关 num 列表]}。
> 4. 输出 JSON 数组，写回 `_units.json`，结构：[{id, name, out:"", files:[...]}]。
> 不要写正文，只做分类与归组。

输出示例（与 `05_精读摘要/{NN}_*.md` 对应，`id` 形如 `"u01"`，`num` 为零填充字符串）：
```json
[{"id":"u01","name":"境内IPO实务（申报与审核）","out":"","files":[{"num":"10","title":"...","path":"03_逐字稿/10_xxx.txt"}]},
 {"id":"u02","name":"港股上市路径","out":"","files":[{"num":"04","title":"...","path":"03_逐字稿/04_xxx.txt"}]}]
```

## Step 4 · Fuse（跨视频熔合）Prompt 模板

对每个 unit 调用一次（可后台分批，每批 3–4 个）。

> 你将把以下视频/图文的逐字稿，熔合成一篇**逻辑连贯的精读长文**。
> 源材料：unit「{name}」，包含视频编号 {files}。请先 Read 每个 `03_逐字稿/{num:02d}_{title}.txt`。
>
> 写法要求：
> 1. **去口语化**：去掉"呃、那个、对吧"、口播套话；保留实质信息与案例。
> 2. **立逻辑骨架**：按主题重组为 `## 一、二、三…` 章节，不要简单拼接；跨视频重复内容合并，互补内容整合。
> 3. **保留案例**：原文中的真实交易 / 案例 / 数据务必保留（可匿名或校正名称，但注明来源视频编号）。
> 4. **篇幅不限**，以讲清楚为原则。
> 5. 顶部先写 `# {长文标题}` 与一段引言（本篇覆盖什么、融合哪几个视频），**先不写溯源区块**（Step 5 注入）。
> 6. 写回 `05_精读摘要/{unit:02d}_{一级类}_{短名}.md`。
>
> 质量红线：事实准确、不编造、不遗漏关键案例。

### 熔合 vs 单篇（为何必须跨视频）
- 单篇摘要：用户反馈"看不懂、逻辑散"——因为单条口播本就碎片化。
- 跨视频熔合：按主题把多期内容立成骨架，用户反馈"是我想要的内容"。
- **结论：默认跨视频熔合，不为单篇单独出文**（除非用户明确要单篇速读卡）。

## Step 5 · Provenance + Time Anchoring 细则

### 文档级来源区块（每篇开头，紧跟标题/引言之后）
```markdown
> **来源视频（共 N 个，按发布时间排序）**：
> #135 (2023-08-05) 标题、#122 (2023-11-10) 标题、#92 (2024-06-21) 标题
> #81 (2024-09-06) 标题、#70 (2024-11-22) 标题
> 本篇融合视频发布于 2023-08-05 ~ 2026-03-28；文中「近期／近几年／当年」等时间词指各视频发布时点前后。
```
- N = 本 unit 的 files 数；日期取自 `_provenance_map.json`
- 编号按发布日期升序排列
- **务必原样保留**，写回文件时不可删改

### 段落级标注（正文每段末）—— 本流程核心交付之一

**标注格式（两种，按归因粒度选用）：**
- 单源：`（来源：视频#N，发布 YYYY-MM-DD）`，N=归因视频编号，日期=该视频发布日期
- 多源（一段融合多个视频内容时）：`（来源：视频#N、#M，发布 YYYY-MM-DD、YYYY-MM-DD）`，
  或日期不明时简写 `（来源：视频#N、#M）`。多源比"强行归单一视频"更诚实，**优先用多源**。

**模糊时间词替换（锚定，以归因视频发布日期为基准）：**
- `近期 / 最近 / 目前 / 现在` → `近期（约 YYYY 年 MM 月）`
- `近几年 / 这几年 / 当年 / 前几年` → 依语境替换为具体年份或时段，如 `近几年（约 2023–2025）`
- 锚定要自然、不破坏原意；若标注为多源，时间词锚到其中最早视频的时点即可。

**归因方法：** 读 `03_逐字稿/` 下源视频原文，判断每段最源自哪个视频。
综合/过渡段：若融合多视频，用**多源标注**；若确属单一最相关视频，归该视频；实在无法判断，归本单元最早发布视频。

**勿破坏：** `##`/`###` 标题、表格、代码块、`---` 分隔线、文档级来源区块保持原样；列表项若源自明确视频可在项末加标注（不强制）。

### 段落级标注 Prompt 模板（后台分批，带跳过规则）★复制即用
> 你是溯源标注代理。处理长文 `05_精读摘要/{file}`（unit「{name}」，融合视频编号 {files}）。
> 1. **跳过规则**：先 Grep 该文件是否含 `（来源：视频#`。若已含 → 回报 skip，不重复写。
> 2. 读 `_provenance_map.json` 取 num→date；**Read** `03_逐字稿/{num:02d}_{title}.txt` 每个源视频原文做段落归因。
> 3. 保留顶部文档级来源区块、`---` 分隔线、`##`/`###` 标题层级不动。
> 4. 重写正文：
>    a. 模糊时间词 → 具体年/时段（单源锚归因视频日期；多源锚最早视频日期）。
>    b. 每段末加内联标注：单源 `（来源：视频#N，发布 YYYY-MM-DD）`；融合多视频用多源 `（来源：视频#N、#M，发布 …）` 或 `（来源：视频#N、#M）`。
> 5. **Write 写回原文件**（必须包含：原文档级来源区块 + 改写后正文）。
> 6. 汇报：done（标注段数）/ skip。
> 质量红线：事实不准、编造来源、误删文档级区块均为事故。

### 生成索引与质量门禁
- `python scripts/build_provenance.py <workdir>` → 读 `_ingest.json` 写 `_provenance_map.json`
  - 加 `--strict`：有 item 缺 date 则中止（退码 2）；加 `--merge`：与现有 map 按 num 合并（增量更新用）
- `python scripts/gen_index.py <workdir>` → 读 `_units.json` + `_provenance_map.json` 写 `05_精读摘要/溯源与时间索引.md`
- `python scripts/verify.py <workdir>` → **质量门禁**：校验每篇含文档级区块、段末标注有效、日期与 map 一致；不通过退码 1。每次跑完务必执行并清零错误。

### 增量更新（博主发了新内容时，不用全量重跑）
1. adapter 重新全量爬取博主主页 → 覆盖 `_ingest.json`（含全部历史 + 新内容）
2. `python scripts/incremental.py <workdir>` → 对比现有 `_provenance_map.json`，产出 `_ingest_new.json`（仅新增）并打印新增/失效报告
3. 只对 `_ingest_new.json` 里的 item 跑 Step2~5 熔合新长文（可后台分批）
4. `python scripts/build_provenance.py <workdir> _ingest_new.json --merge` → 追加到 `_provenance_map.json`
5. `python scripts/gen_index.py <workdir>` 重生成索引

### 转写（视频无现成字幕时）
- 优先用 `python scripts/transcribe.py <workdir>`：自动找同名字幕(.srt/.vtt/.ass)清洗成 txt；无字幕且装了 `openai-whisper` 则转写；否则跳过并提示。
- 若 whisper 不可用：在隔离 venv 执行 `pip install openai-whisper` 后重跑；或确保 adapter 阶段已拿到平台字幕/文稿。
