# 公众号版：首图逻辑和小红书有什么不一样（10-13 起）

同一篇 meme 稿发到微信公众号时读这页。正文一个字不改（10-07 到 10-21 规则冻结，公众号分支只动输出层），改的只有三样：首图、标题长度、摘要。脚本 `scripts/render_wechat.py`。

## 一、两个平台的首图不是同一个东西

| | 小红书 | 公众号 |
|---|---|---|
| 首图出现在哪 | 双列瀑布流，一屏同时有 4 到 6 张封面，标题在图下面另起一行 | 三个地方：订阅号消息列表（2.35:1 横幅，标题在图下或压在图上）、群聊 / 私聊转发卡（1:1 小方图，约 110px，标题在左）、朋友圈转发（1:1 小图 + 标题） |
| 尺寸 | 3:4 竖图 1080×1440 | 一张原图同时裁出 2.35:1（900×383 或等比放大）和 1:1 两个版本；默认 1:1 取横幅正中间的正方形 |
| 谁在看 | 陌生人，算法推的；读者没听过这个号 | 大半是已关注的人，加上被朋友转发的人；读者认得这个号，或者认得转发的那个朋友 |
| 读者当时在干什么 | 刷，手指停不停看封面 0.5 秒 | 在消息列表里挑一篇点开读，或者在群里看一眼要不要点 |
| 首图的活 | 从 5 张图里把眼睛抢过来，和标题分工：图负责反差，标题负责可搜词和数字 | 让标题显得值得点；在群聊 1:1 缩略图里认得出是这个号、这件事 |
| 首图能不能是正文 | 能。meme 版第 1 页就是正文页，手机长文截图本身是钩子 | 不能。公众号的封面不进正文，正文是网页，图文分开。把 3:4 的第 1 页直接裁成 2.35:1，headline 会被切掉半截 |
| 重复版式 | 没用。每次都是陌生人，版式认不认得出无所谓 | 有用。同一批人每天在列表里看到，固定版式三五篇之后变成「一看就是他发的」 |
| 文字量 | headline 20 字以内可以读，缩略图有半屏宽 | 横幅能放 2 到 3 行大字；1:1 缩略图只有拇指大，能读的是 2 到 6 个字 |

一句话：小红书的首图是「拦人」，公众号的首图是「给已经认识你的人一个点开的理由，并且在群里转发时像一张名片」。

## 二、从这个差别推出来的做法

1. **横幅正中间的那个正方形是安全区**。公众号后台用同一张图裁 2.35:1 和 1:1，1:1 默认取中间。所以大字放在正中间的正方形里，素材图放在正方形外面的左右两侧。横幅里是「大字 + 素材图」，裁成 1:1 自动变成「只剩大字」，群聊缩略图里反而更清楚。
2. **大字不是标题的复述**。标题在图下面已经有了，公众号标题可以写到 64 字。图上的大字是标题里最扎人的那 6 到 12 个字，分 2 到 3 行，每行不超过 6 字，`==词==` 给一个词打黄底。小红书那套「数字 + 社会证明 + 痛点动词 + 可搜词」还是写进标题，不上图。
3. **素材图放边上，不放中间**。小红书首页的 `hero` 是正文第 3 段后面的证据图；公众号横幅里它只是配角，放在右侧安全区外面，裁成 1:1 时丢掉也没损失。没有合适的素材图就不放，白底大字比硬配一张图好。
4. **左上角固定一个账号章**（头像 + 账号名）。这是给订阅号列表里的老读者认的；小红书首页由平台带头像，公众号列表里头像很小，要自己放一份进图。
5. **横幅底部留 90px 不放字**。多图文群发时，头条的标题会压在横幅下沿，大字放在底部会被盖住。
6. **颜色维持白底 + 黑字 + 黄底高亮**。和小红书版一个体系，读者在两个平台看到是同一个人。黑体，不用宋体（用户 10-03）。
7. **摘要要写**。公众号转发到群里和朋友圈时，卡片上标题下面那行是摘要（不写就默认取正文头 54 字）。摘要用第一段的那句判断，120 字以内，不写「本文介绍了」。
8. **正文页图不进公众号正文**。公众号正文用 draft.md 的文字，证据截图和对照图按原位置插进去，领取物直接接在文末（公众号没有图下文案，也没有标签）。

## 三、front matter（都可选，写在 draft.md 里）

```
wechat_cover: 别跟 AI 说<br>==高级一点==      # 横幅大字，2 到 3 行，每行 6 字以内，==词== 打黄底。不写就用 headline，再不写用 title
wechat_kicker: 用 Claude 干活两年            # 大字上面一行小字，16 字以内。不写就没有
wechat_hero: map.png                        # 右侧素材图，不写就用 hero；写 off 不放图
wechat_digest: 一句摘要，120 字以内            # 不写就取第一段
wechat_title: 公众号标题（64 字以内）           # 不写就用 title
```

## 四、出图和检查

```bash
python3 $M/scripts/render_wechat.py "<输出目录>/meme版/编辑用/draft.md" "<输出目录>/公众号版"
```

出：`封面.png`（1800×766，上传后后台裁 2.35:1 用整张、1:1 用默认居中）、`封面_1x1预览.png`、`预览.jpg`（模拟订阅号列表、群聊转发卡、朋友圈三处的样子）、`标题.txt`、`摘要.txt`、`正文.md`（公众号正文，图按文件名引用，文末接领取物）。

脚本会拦：大字每行超过 6 字、总字数超过 16（✗，1:1 里读不出）；大字出了安全区（✗）；标题超过 64 字（✗）、超过 30 字（⚠，列表里会折成两行以上）；摘要超过 120 字（✗）；素材图太暗（⚠，沿用 render_meme 的亮度判定）；标题和大字里有极限词（✗）。

Read `预览.jpg`：三个场景里，群聊那张 1:1 缩略图能不能一眼读出大字；订阅号列表那张，图和标题是不是在说同一件事。
