# 小红书漫画讲解（K 老师）

和「五图知识卡」并列的另一种图文格式：不摆数据卡，而是**让 IP 演一个小故事**，读者跟着故事走完就懂了原内容的逻辑。

`$M` = 本 SKILL.md 所在目录；`$X` = 同级的 `xiaohongshu-wutu-zhishika`（截图引擎和头像在那边，两个 skill 要一起安装）。

## 固定 IP（不要改造型）

| 角色 | 造型 | 戏份 |
|---|---|---|
| **K 老师** `ein` | 灰色炸毛、灰胡子、吐舌头、黑外套黄领带（就是账号头像那个小人）。名字取自账号 **K**rypto说AI，图上、签名、栏目名一律叫「K 老师」 | 主角。看穿问题的人，嘴有点欠但讲得明白；每期结尾由他收束 |
| **小白** `xiaobai` | 三根呆毛、灰 T 恤 | 配角。替读者提问、踩坑、不服气 |

强调色只有黄色 `#FFE600`（头像底色）。造型、配色、道具都在 `scripts/characters.py`，新道具加到 `PROPS` 里，不在 comic.json 里临时画。

## 步骤

1. **先列「必保清单」**（写进 `图文版/编辑用/story.md`）：漫画是换一种讲法，不是删内容。从原内容里挑出——
   - **核心关键词** 1 个：这期到底在讲什么（产品名 / 概念名 / 人名），嵌进封面问句、标题和标签
   - **读者的痛点** 1 句：这件事和读者有什么关系、他现在正在吃什么亏——封面引子和问句从这里来
   - **关键概念** 3–6 个：保留原名（英文术语不翻译，如 Choice / Score / System One），每个配一句人话解释
   - **关键句** 2–4 句：原内容里最值得记住的判断，译成中文放进 `quote`；一句一页，不堆在一起
   - **硬数字和案例**：价格、耗时、谁用它做了什么，连同口径（不含什么、没做什么）
   - **逻辑链**：一个核心问题 + 4–7 步推理 + 一句结论
2. **再编故事**：按 `templates/story_rules.md` 找一个生活场景装这条逻辑链。**比喻只负责讲「为什么」，「是什么」用真名讲**——故事演完，`note` / `quote` 里要马上落回真实的术语、机制和数字。没想好故事不要动手排页
3. 写 `图文版/编辑用/comic.json`（格式见 `scripts/render_comic.py` 顶部注释，样例 `samples/jev/comic.json`（配套的必保清单在 `samples/jev/story.md`）），复制 `$X/assets/avatar.png` 到同目录
4. `python3 $M/scripts/render_comic.py 图文版/编辑用/comic.json 图文版/`（脚本会先检查：封面有没有 kicker、title 是不是问句、是不是只有一个人且没台词，图上有没有「转述腔」禁用词，不过就不出图）
5. **对着必保清单逐项打勾**：每个关键概念、关键句、数字，都能指出它在第几页。漏了就加页（上限 13 页），不要为了凑故事把它删掉
6. **Read overview.jpg 检查**，有问题改 comic.json 重出：
   - 文字压到人物 / 最后一段被挤出画面 → 删字或把 fig 的 height 调小，不要缩字号
   - 页面下方空了一大块 → 加内容（要点、关键句），或把 fig 的 height 调大
   - 台词超过 2 行 → 压到 22 字以内
   - 连续 3 页同一个姿势表情 → 换 pose / face
   - 单看图、不读正文，能不能看出这页在演什么
7. 标题.txt / 正文.txt / 标题备选 / 系列期数 / check_paste 沿用 youtube-xhs 步骤 6–7 的规则。栏目名默认「K老师讲AI｜第 N 期」。**出处只写在 正文.txt 里**（「来源：……」那一行），图上不写

## 图上的文字（和知识卡版的区别）

漫画是 K 老师在**讲这件事本身**，不是在转述一篇帖子。所以图上：

- **不出现**「原帖」「原文」「作者」「博主」「这篇文章」「X 爆帖」「视频里说」这类转述腔，也不在封面加「X 爆帖：」「XX 长文：」这类信源行——那是知识卡版的规则，漫画版不用
- 数字和结论**直接陈述**：写「Jev 每百万输入 token 0.042 美元」，不写「作者给的账是……」
- 要引用别人的原话，用 `quote` 引用块，前面可以署名到机构或产品（「Browser Use：……」），不署「作者」

## 封面（最重要的一页）

封面只干两件事：**让人点进来，让人想关注**。版式学的是对标账号的首图规律（记在记忆 xhs-cover-benchmark）：三层字 + 一个人演一件事，主页网格上一眼能认出。

| 位置 | 字段 | 写什么 |
|---|---|---|
| 顶部 | `kicker` | **黄底小字引子**，一行：场景或情绪，把读者拉进那个处境。「开了 10 个 Agent 之后…」「跑一小时就跑偏？」「测试全绿，功能是坏的」 |
| 最大的字 | `title` | **超大问句**，2 行，写成「为什么你的… / 如何… / 怎么才能…？」。说读者自己的事，产品名直接嵌进去（「为什么你的 Agent 越多越乱？」）。脚本按最长一行自动缩字号，缩到难看就删字。关键那几个字用 `==` 标黄 |
| 画面 | `scene` | **只有一个人 + 1–3 个道具，把这件事演出来**。默认 K 老师，`face: "meh"`（无语脸）是封面招牌表情；道具要一眼能看懂（缠成一团的线牵着三个机器人 = Agent 越多越乱）。**不配台词**：缩略图上看不清 |
| 底部 | 顶层 `series` | 只放栏目名「K老师讲AI｜第 N 期」，每期同一个位置、同一个样子 |

不放 `keyword` 黄底关键词块、`sub` 副标题、`promise` 承诺行、两个人对话——这些在手机缩略图上都是噪音。搜索关键词放进 标题.txt 和标签。脚本会拦：没有 kicker、title 不是问句、人数不是 1、有台词、还写了 keyword / sub。

**三版封面**（`covers.json`，画面相同，只换 kicker + title）：

1. **痛点**：读者正在吃的亏。「开了 10 个 Agent 之后… ／ 为什么你的 Agent 越多越乱？」
2. **数字**：原内容里最大 / 最小的数，写成问句。「跑一小时就跑偏？ ／ Agent 怎么才能连跑 16 天？」
3. **反常识**：一个违背直觉的现象。「测试全绿，功能是坏的 ／ 为什么 AI 写的测试抓不到 bug？」

**封面硬规矩：**

1. **只提问，不给答案。** 结论写在封面上，读者就不用点了
2. **钩子不用故事里的比喻。** 封面在故事之前，读者还不知道「装修」「大厨」是谁
3. **价格用「约」，不用「只要 / 仅需 / 低至」。** 产品名 + 价格 + 促销词是广告句式，平台会当成未报备推广。脚本会拦
4. **不编数字**：钩子里的数必须是原内容里有的，口径不能变；数字以幻灯片 / 课件为准，自动字幕残缺的地方不要猜
5. 不用「震惊」「必看」「99% 的人不知道」

`标题.txt` 同理：不以读者不认识的产品名开头，标题讲痛点、留「为什么」。

检查钩子：
- 把产品名遮住，这句话还能让人想点吗？不能就重写
- 有没有「你 / 你的」或读者一眼认得出的处境（账单、加班、跑偏、被老板问）
- 缩到手机主页网格那么小，还能看清问句和人在干什么吗

**转粉靠一致的版式**：读者点进主页，看到每张封面都是「黄底引子 + 大问句 + 无语的 K 老师 + 栏目名」，才知道关注了会持续得到什么。不写「求关注」。

## 内页版式（读者不疲劳的关键）

**只有封面用大人物。** 内页是「文字主导 + 小图解」：人物是图解里的一个元素，帮着解释概念，不是站在那里摆 pose。内页一律用 `panel` 页（旧的 `story` 页只为兼容保留，新内容不要用）。

一页 `panel` = 一串 blocks，从上到下排：`lead`（小字引入）→ `h`（大标题，可两行）→ `p` / `ul`（段落、要点）→ `fig`（图解）或 `rows`（图标行）→ `quote`（关键句）→ `p`（落回真实术语和数字）。

**每页 120–260 字**（脚本拦 <90 和 >300）。标题 + 一段引入 + 3 个要点 + 一句关键句，是比较舒服的量。

**六种图解，混着用：**

| 版式 | 怎么写 | 适合 |
|---|---|---|
| 双人对戏 | `fig.actors` 两个人 + `say` | 故事情节：谁犯了错、谁戳破 |
| 左右对比 | `divider: true` + 两个角色各带 `label` | 两种角色 / 两种做法的分工 |
| 人物 + 标签 | 一个人 + 几个 `tags`（可加 `arrows`） | 一个东西的几个方面、几个用途 |
| 条形对比 | `bars` | 前后对比、大小悬殊的两个数 |
| 流程 | `flow` | 分工链、步骤 |
| 图标行 | `rows`（不用 fig） | 并列的 3–4 个概念，每个一个小图标 + 名称 + 一句解释 |

**角色变体**（同一个人反复出现就腻）：
- `bot` 方头机器人 = AI / Agent / 模型本身；`accent: true` 系黄领带，代表这期的主角模型
- 任何角色可以 `hat`（戴道具，如厨师帽）、`hold`（拿道具）、`meter`（头顶进度条）、`label`（脚下写它代表谁）
- 比喻里的角色用变体来演：大厨 = 戴厨师帽的 bot，领班 = 黄领带 bot。K 老师和小白只在需要「人」的情节里出场，不必每页都在

**脚本会拦的：** 内页人物 `scale` > 1.7；连续三页版式一样；全篇版式少于 4 种；超过三分之一的页是「一个人干站着、旁边什么都没有」。

## 页面结构（9–13 页）

| 页 | type | 内容 |
|---|---|---|
| 1 | `cover` | 钩子封面，见上面「封面」一节：`kicker` 黄底引子 + `title` 大问句 + 一个人配道具（不带台词）+ 栏目名 |
| 2 | `panel` | 故事开场：小白遇到的麻烦（= 原内容要回答的问题）。kicker 写「故事是这样的」之类 |
| 3–N | `panel` | 每页一个情节 = 一步逻辑。`no` 编号 01 02 03…；上半页讲情节，图解演出来，`quote` 放原内容的关键句，最后一段 `p` 点破它对应的真实概念——**每页至少有一个真实术语或数字** |
| 中段 | `panel` | 允许 1–2 页「说回正题」的概念页：不演情节，K 老师直接用 tags 把真实机制摆出来（三种题型、四个用法、价格表）。kicker 写「说回正题」 |
| N+1 | `panel` | 「回头看」：跳出故事，用 tags 对比图把结论说透 |
| 末页 | `end` | 黄圈K 老师 + 2 行金句 + 签名「漫画学AI，我是 K 老师～」。不写求关注 |

一页只讲一件事，120–260 字。内容多就加页，不要把两个概念挤进一页，也不要为了页数少把概念删掉。
