# 故事怎么编

目标：读者不看任何术语解释，只跟着故事走，也能复述出原内容的逻辑。

## 1. 先有逻辑链，再找比喻

把原内容写成这样一条链（写在 comic.json 旁边的 `story.md` 里，方便以后改）：

    问题：为什么 ___？
    第 1 步：因为 ___
    第 2 步：所以 ___
    第 3 步：但是 ___（转折 / 常见误解）
    结论：___

然后找一个**人人经历过的场景**去装它：考试、点外卖、租房、装修、相亲、带新人、做饭、赶火车。
好比喻的标准：逻辑链的每一步，在这个场景里都有一件**对应的事**发生。只有开头像、后面对不上的比喻不要用。

例：RAG → 开卷考试。闭卷硬答 = 幻觉；资料柜 = 向量库；翻错页 = 检索质量决定效果。

## 2. 四拍结构

| 拍 | 页 | 故事里 | 对应原内容 |
|---|---|---|---|
| 起 | 第 2 页 | 小白遇到麻烦 | 原内容要回答的问题 |
| 承 | 3–6 页 | 小白按直觉做，翻车；K 老师给办法 | 主要论点，一页一步 |
| 转 | 1–2 页 | 办法也出了岔子 / 小白不服 | 原内容里的「但是」、反直觉的点、常见误解 |
| 合 | 回头看 + 末页 | K 老师跳出故事说人话 | 结论 + 账号自己的立场：一句**可以被反对的判断**（谁按这套做会失败 / 我不同意哪一点），再问读者站 A 还是 B。只有结论没有立场，读者收藏完就走 |

「转」不能省。没有转折的故事就是换了皮的说明书。

## 3. 一页怎么写

- `text`（画面上方）只讲故事：谁做了什么、发生了什么
- `note`（画面下方）只做翻译：这件事 = 真实世界里的什么。真实术语、硬数字放这里，用 ==高亮== 标出
- 台词（`say`）写人话，≤22 字，小白负责问和犯错，K 老师负责一句话戳破
- 画面要在演这一页的情节：翻车用 `cross` / `sad`，想到办法用 `bulb` / `happy`，对比用两个 tags + `arrow`

## 4. 别把原内容讲没了

故事容易把内容越讲越薄。三条硬规矩：

- **比喻讲「为什么」，真名讲「是什么」。** 「领班」可以解释为什么要有决策层，但读者最后要记住的是 Jev、Choice / Score / Noul、System One，不是「领班」。每个比喻角色第一次出场时，当页 `note` 就要点破它的真名
- **关键句原样保留。** 原内容里最锋利的那几句判断，译成中文放进 `quote`，不要用故事情节去「演」掉它。最好的情况是原句自己就带比喻（「否则你的决策模型是在昨天的菜单里点菜」），直接让它和故事咬合
- **数字带着口径走。** 「7 秒、0.0039 美元」后面跟着「不含浏览器成本、不订票」，少了后半句就是误导

自查：把 12 页的 `note` 和 `quote` 单独抽出来连着读，应该是一份能独立看懂的原内容摘要。读不通，说明故事吃掉了内容。

## 5. 不要做的事

- 不要让K 老师站着念要点——那是知识卡，不是漫画
- 不要每页换一个新比喻，全篇一个场景用到底
- 不要为了故事改事实：数字、结论、谁说的，全部以原内容为准；故事里编的情节不能冒充真实案例
- 原内容本身就是一个故事（创业经历、事故复盘）时，不另找比喻，直接让K 老师和小白「重演」它
