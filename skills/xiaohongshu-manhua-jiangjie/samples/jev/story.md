# 必保清单（每项标出落在第几页）

核心关键词：Jev（封面）

关键概念
- System One 模型：给状态 + 预设问题 → 返回带概率的类型化答案；不写简报、不写代码、不解释理由（P4）
- 三种题型 Choice / Score / Noul；Choice 最多 255 项，Noul 近 0.5 = 拿不准（P5）
- 问题要写全：Jev 看不到字段名；证据和请求分开给（P6）
- 每次状态变了就重列选项（Browser Use）（P7）
- 并行提问；问题之间互相看不到答案（P8）
- 置信度不是准确率；选了 DONE 还要另外检查；操作上限 / 花费上限 / 存进度 / 发布要审批（P9）
- 杰文斯悖论（P2）

关键句
- 每个岔路口，都可能在干正事之前先多调一次模型（P3）
- Jev gives those decisions their own model（P4）
- 否则你的决策模型是在昨天的菜单里点菜（P7）
- 一次便宜但判错的决定，可能比判断本身贵得多（P10）
- LLM 创造内容 → Jev 决定下一步 → 代码执行（P12）

硬数字和案例
- Jev 1.13：$0.042 / 百万输入 token，输出不收费；1 万次判断 ≈ $0.42（P10）
- Browser Use 找航班 7 秒 $0.0039；不含浏览器成本，不订票（P10）
- 协议调用中位数 1092 → 101，任务时间 -25%，两版用同样的模型（P8）
- 1018 篇论文分类 $0.08，中位延迟 256ms；邮件分拣；LangChain 模型路由（P11）

逻辑链
问题：Agent 为什么又慢又贵？
1 任务里夹着大量小判断，每个都调一次大模型
2 这些判断是选择 / 打分 / 是非题，不需要生成 → 交给 Jev
3 题要出对：问题写全、选项现列
4 能一起问的一起问
转：有把握 ≠ 做到了；要有停的地方
5 账按完成的任务算
结论：LLM 创造，Jev 决定，代码执行

比喻：小馆子。大厨 = LLM；领班 = Jev；墙上的规矩 = 代码
