# own-xhs：用户自己的判断和日程写成的长文图

10-08 对照小盖《Personal Agent 和 Coding Agent 的本质区别》（`对标/小盖/personalagent_文字稿.md`，拆解在 `对标/小盖/口吻拆解.md` 第四批）得出的结论：把他的 24 条做法学进 meme-xhs 以后，照着写还是被认出是 AI，因为规则描述的是输出的样子，他那篇的活人感来自输入：五个判断是他的，五个场景是他的日程，想到一半的话也是他的。这三样没有规则能生成，只能从用户那里拿。这个 skill 做的事就是：先把这三样问到手，再把它们排成一篇，Claude 不重写用户的句子。

拿他那篇跑 meme-xhs 的检查是 2 ✗ 11 ⚠（假设我 3 处、押注 3 处、我觉得 7 处、结尾对仗、没图、首屏没反差……）。own-xhs 把这些上限全部关掉，只查三样：用户的判断进了没有、用户的日程进了没有、有没有连续几段抽象话。

## 文件

- `$O` = 本 SKILL.md 所在目录：
  - `references/own_guide.md`：写法，对照小盖那篇逐段拆。**写稿前读完。**
  - `references/questions.md`：写稿前先问的模板（摘要 + 三问）。
  - `scripts/own_check.py`：检查。复用 meme-xhs 的 `parse` / `check_title`。
- `$M` = 同级的 `meme-xhs`：出图用 `$M/scripts/render_meme.py`，红框用 `$M/scripts/box.py`，总结图用 `$M/scripts/render_illus.py`，头像 `$M/assets/avatar.png`。版式和 meme-xhs 完全一样，读者看不出两个 skill。
- `$Y` = 同级的 `youtube-xhs`（`check_paste.py`、`post_log.py`）。
- 输出目录：`发布/<YYYY-MM-DD>_<英文短标题>/own版/`。

```
own版/
  01.png … NN.png   overview.jpg
  标题.txt  标题备选.txt  正文.txt
  编辑用/  source.md  输入.md  draft.md  avatar.png  （素材图、总结图）
```

## 写稿前先加载账号记忆

和 meme-xhs 一样：`CLAUDE.md` → `账号/档案.md` → `账号/经历库.md` → `账号/范本/` 一篇 → 才读素材。own 模式下范本固定多读一篇小盖（`对标/小盖/personalagent_文字稿.md`）。

## 步骤

### 1. 素材 → `编辑用/source.md`

和 meme-xhs 第 1 步一样。front matter 里多记一行 `people:`，写原文里出现的人名（逗号隔开），own_check 会查他们在第一段之后有没有再出现。

### 2. 写稿前先问（必走，模板在 `references/questions.md`）

读完素材先不写。发一段 150 字以内的摘要（谁写的、核心判断一句、两三个事实、最可争论的一句原话），然后只问三样，不问「哪种价值」「站哪边」：

1. **日程**：这周（或者最近）你哪天干了什么跟这件事沾边的事，要日期、地点、结果，给三条。见客户、出差、带家人、配 agent、改需求都算。假设式的也行（「假设我下周一带实习生」），标明是假设。
2. **判断**：你对这件事自己的三到五句话，不用整理，语音转文字也行，半截话也要。
3. **两年后**：你觉得两年后这件事会怎样，一句。

回答**原样**存进 `编辑用/输入.md`（格式见 questions.md：`## 判断` `## 日程` `## 原话` 三节，一行一条，不改字）。带日期的日程同时记进 `账号/经历库.md`（假设式的标「假设」，不算经历），判断记进 `账号/档案.md` 观点库。

**判断不到 3 条，或者日程不到 3 条，不用这个 skill**：告诉用户差几条，用户不补就回 meme-xhs（访谈走 retell）。「你定」在 own 模式下不成立，因为没有东西可定。

### 3. 写 `编辑用/draft.md`

读 `references/own_guide.md`。骨架固定，里面全是用户的东西：

- **第一段**：一句点素材（谁、什么、在哪看的）+ 一句意图（「还是想写几点自己的理解」这种），之后素材里的人不再出现。
- **前面两三段**：用户判断里最大的那句，加一个零信息的「正在想」句（用户原话里有就用原话，没有就不写，不编）。
- **编号 1 到 5**：每个编号句就是用户的一条判断（整理成一句，意思和用词不换），编号下面一到三段：先放用户的一个日程场景（带日期地点，假设式的保留「假设我」），再展开一两句为什么。
- **用户原话**：`## 原话` 里的句子原样放进对应的编号下面，含「不知道」「可能吧」「真的来了。真的来了。」这类，不润色。
- **结尾**：停在用户「两年后」那句上，或者最后一条判断上。不总结。
- **可以随便用、不查上限**：假设我、我觉得、我感觉、对未来的话、单句段（前一段是场景就行）、「当然」「总之」「是的」、结尾一句有分量的话。
- **仍然不写**：生产过程的痕迹（「推荐看看」「先说他是谁」「下面是他讲」「整理稿 / 素材里」）、直译味的比喻（「坐标系」「一把尺子」）、给文章打分（「这条我站他」「这点我同意」）、预告、导流、「一、二、三」知乎体（用「1、」）。
- 字数 1800 到 3500；图至少两张（一张素材截图、一张总结或对照），和 meme-xhs 一样。
- Claude 的活：排顺序、写接句（「所以」「比如」「但反过来」）、把用户的半句补成能读的一句。**不替用户生成判断，不替用户编场景**。稿子里哪一句是 Claude 接的，交付时能指出来。

front matter：
```
---
title: （第 5 步定）
mode: own
people: 原文里的人名，逗号隔开
keyword: 主关键词
keywords: 副关键词
hero: 素材截图（可选）
hero_after: 2
time: 26-10-9 21:00
account: Krypto说AI
---
```

### 4. 检查

```bash
python3 $O/scripts/own_check.py "<输出目录>/own版"
```

✗：没有输入.md、判断进稿不足 3 条、日程 0 条、连续 4 段抽象、露生产过程、直译比喻、打分、预告导流、标题超 20 字。⚠：判断原文已说过、日程没日期地点、原话被改写、原文人物第一段后再出现、连 3 段抽象、没数字标题、图少于 2、字数越界、极限词。最后一行「只报数不限」是给自己看的：「我」几次、假设几处、押注几处，和小盖那篇对一眼。

然后和 meme-xhs 一样跑一遍 `skills/xhs-cold-start/scripts/ai_tone.py`，但它报的「我觉得超 4 处」「对仗」在 own 模式下不改。

### 5. 出图、标题、正文、交付

```bash
cp $M/assets/avatar.png "<输出目录>/own版/编辑用/"
python3 $M/scripts/render_meme.py "<输出目录>/own版/编辑用/draft.md" "<输出目录>/own版"
```

- 标题：meme-xhs 第 8 节的公式（数字 + 社会证明 + 痛点动词 + 可搜词），三条备选，最强的写进 `标题.txt` 和 draft 的 `title`。
- `正文.txt`：第一行关注理由 → 要点 → 领取物（有就给，优先提示词 / 配置）→ 标签。
- `python3 $Y/scripts/check_paste.py "<输出目录>"`；`post_log.py add --series own --no <N>`（期数取日志里 own 栏目最大值加 1）。
- SendUserFile：`01.png` 到 `NN.png` 每张单独发，加 `标题.txt` `标题备选.txt` `正文.txt`。汇报：用了用户哪几条判断、哪几条日程、哪几句原话；哪几句是 Claude 接的；own_check 剩的 ⚠。

不登录小红书，不代发。
