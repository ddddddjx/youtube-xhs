# own-xhs：用户的东西怎么进各文体

写法本身看 `../../meme-xhs/references/writing_guide.md`，这里只讲用户给的三样（判断、日程、原话）放在哪。范本：`对标/小盖/personalagent_文字稿.md`（10-03，176 赞 182 藏），拆解在 `对标/小盖/口吻拆解.md` 第三、四批。

## 1. 按文体放

| 文体（meme-xhs 第 2 节） | 判断放哪 | 日程放哪 | 原话放哪 |
|---|---|---|---|
| 转述荐读 | 结尾那句认同或保留、挑三点时的一句；主语仍是原文里的人 | 替掉本来要用原文场景的一两处（「我上周三在香港配 agent 时也碰到……」） | 结尾 |
| 荐读 / 解读 / 观察 | 「很多人觉得……其实」后面的反驳、三点里每点「这说明什么」的那句、结尾判断 | 「放到读者自己身上」那一步，换成用户的那天 | 任一处判断后面 |
| 实测 / 活动见闻 | 判断标准、总判断 | 本来就是用户的真实记录 | 翻车处、评价处 |
| 热点快评 | 「我」怎么看 | 「今天早上我在……」 | 结尾 |
| **自述判断**（`genre: 自述`，小盖式） | 全部编号句 | 每个编号下第一段 | 开头的「正在想」句、各编号的收尾句 |

规矩三条：用户的判断意思和用词不换，可以补成整句；日程照用户给的日期地点写，不加他没说的细节；原话一字不改，带语气词和半截话。

## 2. 自述判断这种文体：小盖那篇 66 段是怎么排的

| 位置 | 他写的 | 来源 | 对应 |

五个编号句全是他的，五个场景全是他的日程，原文一个字没引。

## 3. 五种段落

1. **判断句**：主语是行业里的东西，不是文章。用户给半句就补成一句，用词不换。
2. **日程段**：时间在前，事在后，一段一件事，下一段才讲 AI 会怎么做。
3. **展开段**：两三句，「因为」「所以」「比如」接着走，这是 Claude 唯一大段写的地方，名词用用户工作里的或这周行业里的。
4. **正在想的句子**：只用用户原话。Claude 写的「正在想」一眼假。
5. **一句感叹**：放在具体场景后面单独成段；前一段抽象就不许。

## 4. 对 meme_check 上限的处理

| meme_check 的规则 | own 模式 |
|---|---|
| 「假设我」最多 1 个 | 用户给的日程不算；Claude 自己加的算 |
| 押注最多 1 处 | 用户的判断不算 |
| 「我觉得」最多 4 处 | 用户的判断不算 |
| 结尾对仗 ⚠ | 用户原话不算 |
| retell「我」最多 6 次 | 用户的句子不算 |
| 身份 / 朋友场景 ⚠ | 用户日程里的朋友、同事、家人放行 |
| 结构词孤段、单句总结段、先让步再转折、黑名单、李录四条、标题、图、不预告不导流 | 照旧 |
