# 数据反馈规则

本文件管：后台数据怎么读、能证明什么、不能证明什么、规律怎么记录和更新。

## 一、后台表字段（小红书「笔记列表明细表」导出）

当前表有 13 列：笔记标题、首次发布时间、体裁、曝光、观看量、封面点击率、点赞、评论、收藏、涨粉、分享、人均观看时长、弹幕。表头第一行写明「最多导出排序后前 1000 条笔记」。

| 字段 | 怎么理解 | 注意 |
|---|---|---|
| 曝光 | 笔记被展示的次数 | 累计值，发得越早累计越多 |
| 观看量 | 被点开观看的次数 | 包含搜索、主页等入口，不只来自曝光 |
| 封面点击率 | 平台给出的点击率 | 与「观看量 ÷ 曝光」接近但不相等，按平台值用 |
| 收藏、点赞、评论、分享 | 互动次数 | 用「收藏 ÷ 观看量」比较内容是否值得留 |
| 涨粉 | 归因到这篇笔记的新增关注 | 多数笔记为 0，看合计和每千次观看涨粉 |
| 人均观看时长 | 秒 | 图文和视频不可直接比 |

表里**没有**：私信数、咨询数、成交数、栏目、题材类型、流量来源（搜索/推荐）、导出日期。因此：

- 阅读、收藏、涨粉都不能当作咨询转化。咨询效果需要另行记录（私信数、有效咨询数、成交），在此之前写「无法量化」。
- 导出日期要从数据推断（最新几篇曝光为 0 时，导出时间接近其发布时间），并在结论里写明。

## 二、读数据的规矩

1. **写清范围**：样本篇数、发布时间段、导出日期、分组方法。
2. **统计窗口**：表内是截至导出日的累计值。比较不同时期时，新发的笔记被低估；最近 7 天内发布的笔记不进入比较，或单独标注。
3. **用中位数**：单篇爆款会拉高平均数。当前表里观看量最高的 10% 笔记贡献了 55.6% 的总观看。
4. **小样本标注**：一组少于 10 篇时只作线索。
5. **相关不等于因果**：发布时间、题材、标题、体裁、同日篇数会同时变化。写结论时说明可能的混杂因素。
6. **分组方法要能复现**：按标题关键词分题材时，写出关键词规则，并承认会有误分。
7. **未发布稿不算数**：草稿、样稿、自评高分稿都不能证明有效。
8. **视频和图文分开看**：视频观看量口径不同。

## 四、怎么更新规律

1. 拿到新导出表时，先记录导出日期和覆盖时间段。
2. 用和上次相同的分组规则重算，变化写进上表「观察」列，并注明新旧两期的样本量。
3. 只有对照实验（见 [topic-planning.md](topic-planning.md) 第七节）支持的结论才能标「已验证」，才可以写成写作规则；线索只能影响选题优先级。
4. 任何规律都不能变成标题公式或固定句子。
5. 在原项目里，规律同步写入 `自适应学习/账号学习状态.json`；没有该文件时，就维护本表。
6. 正文不提及内部数据文件。
