# 身份与事实规则

本文件管两件事：正文里的「我」能写什么，正文里的事实从哪里来。写作手法见 [writing-style.md](writing-style.md)。两者冲突时，本文件优先。

## 一、「我」是谁

- 小熊先生正文里的「我」是账号作者本人（原 Skill 中记作 Stephen），不是团队，也不是任何素材作者。
- 账号名在作者确认改名前一律写「小熊先生」。正文不用第三人称称呼自己，不写「我们团队」「小熊先生认为」。
- 林木求职或其他博主、受访者、学员、评论者的经历和观点，永远保留原归属，不能改写成「我」的经历。

## 二、已确认可写的个人信息

作者亲口确认后，在下面逐条登记：内容、可写到什么程度、确认日期。正文只能写到登记的程度。

| 内容 | 可写程度 | 确认日期 |
|---|---|---|
| 职业：从事股权投资，主要看成长期、Pre-IPO 及中后期项目；工作覆盖项目获取、行业研究、商业尽调、估值分析和交易推进 | 可写「我做股权投资」「我看 Pre-IPO 项目」，不写机构名 | 2026-10-12 |
| 过往经历：TMT 行业研究与 IPO 商业尽调、美元基金及投后，参与过机器人和消费领域的投资项目 | 可写到这个程度，不写机构名、具体项目名 | 2026-10-12 |
| 研究重点：机器人与具身智能、半导体、AI 基础设施（算力芯片、网络互联、存储、供电、散热） | 可写 | 2026-10-12 |
| 看项目的习惯：结合产业和交易条件，看竞争优势、客户需求、增长质量和现金流，也看入场估值、融资安排、上市路径和退出流动性；关心技术进步和商业兑现之间的距离 | 可写成「我看项目时」 | 2026-10-12 |
| 实习：四大审计、券商 IBD、战略咨询 | 可写「我实习过……」，不写机构名 | 2026-10-12 |

| 观点：能拿到结果的人靠好奇心和专业做事的能力；选第一份工作不该把 exit 放第一位；靠忍耐换高薪走不远；钱是结果，认知才让人羡慕 | 作者原话，可直接用 | 2026-10-12 |

2026-10-12 作者首次登记。表里没有的仍然不写：机构名、具体职位和职级、从业年限、辅导人数、招人或面试别人的经历、「我带过的实习生」之类句子。作者的咨询经历只写到「来找我咨询的学生」，不编具体学生的故事。

作者在某次任务里当场提供的经历，只用于当篇，按他给的程度写；他要求登记时才写入上表。

### 待作者确认的事项

确认前不当事实写，也不在正文暗示：

1. 09-19 投行简历辅导录音中的求职导师是否作者本人，其中判断能否作原话用。
2. 7 月旧稿出现过的「我辅导过不少」「我待过大厂」「创业之后才明白」是否属实。
3. ~~可公开的身份边界~~：2026-10-12 已按上表确认（股权投资、Pre-IPO、TMT 研究与 IPO 商业尽调、美元基金及投后）；香港、港股 IPO 是否可写仍待确认。
4. 招人、面试、看项目的真实习惯能否写成「我的习惯」。
5. 私信之后的实际流程：谁回、多久回、是否收费。
6. 作者的强观点、想停掉的题目、能接受的敲打尺度。
7. 「主场」的公开说法：正文写「这块不是我的主场」等于对外声明作者有主场。作者确认可公开的专业背景前，这句改写成对内容范围的说明，例如「下面只讲财会岗位里的通用做法」。

## 三、没有经历时，信任从哪里来

不能靠履历时，靠下面这些可检查的东西：

1. **岗位事实**：这个岗位每天交什么东西、交给谁、谁来复核、出错的代价在哪。来源见第四节。现场细节先从 [industry-details.md](industry-details.md) 取。
2. **招人一方的考虑**：用公开材料能支撑的理由解释招人方为什么看重某件事，例如准则要求、岗位描述原文、招聘公告里的筛选条件。写成推断时要标明是推断。
3. **能直接用的东西**：一句面试里能说出口的话、一个能当场核对的问题、一份读者能照着改的简历句子。
4. **说清自己判断不了的地方**：哪条信息会改变答案、这条信息在读者手里还是在用人单位手里。

「如果你问我」这类个人偏好句可以用，但它表达的是判断，不能顺带暗示经历。

## 四、事实来源分级

| 级别 | 来源举例 | 正文写法 |
|---|---|---|
| A 一手 | 准则与应用指南原文、监管文件、公司招聘公告与岗位描述原文、年报与公告 | 可直接陈述，写出来源名称和日期，必要时给段落号 |
| B 可靠二手 | 主流财经媒体报道、行业协会公开数据 | 写出来源；涉及数字时注明统计时间 |
| C 经验型说法 | 博主分享（含林木）、论坛帖、评论区 | 不当事实陈述；要用时写明「有人这样讲」并说明它适用的阶段和行业，或改成作者自己的判断并说明理由 |
| D 推演 | 作者设定的情境 | 标明「设想一下」「举个设定」，全篇设定一次，写出设定条件 |

规则：

- 薪资、人数、比例、录用率、回复时限、截止日期，只写 A、B 级来源里查得到的，写清时间。查不到就不写数字，改写成读者可以自己去确认的问题。
- 岗位描述（JD）只引用原文并注明公司、岗位名、获取日期。没有原文时不编 JD 句子。
- 公司流程（几轮面试、谁面、多久出结果）各家不同，没有公告支撑就写成「常见做法」，并提醒读者以自己收到的通知为准。
- 政策、招聘信息类内容写出原始发布时间；旧材料按旧材料写，不包装成新消息，不补写材料之后的走势。
- 读者原话只用真实评论、作者提供的脱敏私信或当次材料。没有时用第二人称写处境，不写「很多人问我」「后台有人私信」。

## 五、不确定时怎么写

- 只有一个条件会改变答案时，直接写这个条件：「如果你投的是税务组，这条不适用，因为……」。
- 确实不知道的，直接说不知道，并告诉读者去哪确认：「各所实习生能不能独立跟进回函，我没有可靠资料，入职第一周问带你的 senior。」
- 不写「据调查」「很多 HR 认为」「业内普遍」这类没有出处的概括。

## 六、引用他人

- 学林木的写法（结构、视角、节奏）不需要在正文署名。
- 用到林木或其他作者的具体观点、案例、数据、比喻时：要么注明出处，要么不用。不把他们的学员故事、成交案例、课程结果写进小熊的正文。
- 真实从业者的原话可以引用（作者 2026-10-12 同意），例如「一位做了五年 IPO 的 VP 跟我说」。前提：这个人真实存在、本人同意被引用；正文写清对方岗位，不写可识别身份；按 C 级来源处理，来源清单写明是谁、什么时候说的。没有真人原话时不编。
- 不复制他人标志性句子、故事、比喻、章节顺序和口头禅。

## 七、隐私和情绪安全

- 读者或作者提供的案例去掉姓名、学校、公司、可识别细节；涉及公司内部信息的不写。
- 读者表达自伤、轻生或严重绝望时，停止职业建议，建议寻求专业帮助（如当地心理援助热线或就医）。作者确认付费咨询流程前，不为这类情况设计私信话术。

## 八、服务表述

- 作者已确认的服务：简历修改、职业规划可以作为私信邀请写出。
- 未确认前不写：回复时间、免费、名额、价格、保 offer、保面试、提升通过率之类承诺。
- 不留微信、手机、二维码、外链。
