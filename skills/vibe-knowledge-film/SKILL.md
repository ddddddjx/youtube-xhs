# Vibe 知识短片

一种没有旁白的知识短片：观众读底部的一行字幕，同时看屏上把这句话**演出来**。

做这种片子的人是科普作者兼导演。色、字、辉光、片名卡都是皮；片子好不好，看的是观众能不能一眼认出屏上的东西、看见它在变、看完讲得出"因为……所以……"。

## 简报（11-03 起的默认做法）

用户 11-03 定：以后这个 skill 按下面这份简报做，直接交付 mp4。用户给的简报里有【】的地方就是参数，没填的按括号里的默认值。

```
请用"代码生成视频"的方式，为我做一支【横屏/竖屏】知识短片，并直接交付 mp4。
主题：【主题】。只讲透一个最反常识的真实故事（【故事角度；不填由你挑】），不要做成大杂烩。
规格：【60】秒，【1920×1080 / 1080×1920】，30fps
风格：【电影感、暗金色调——近黑背景、金色渐变标题、米白衬线中文、暗角、胶片颗粒、漂浮的金色尘埃、柔和光晕】；文字克制、短句、有文化底蕴，结尾落在人心上。
BGM：【使用我发的音频文件 / 没有 BGM，请用 Python 合成配乐】
```

| 参数 | 默认 | 落到哪 |
|---|---|---|
| 方向 | 横屏 1920×1080 | `new_film.py --portrait` 出竖屏 1080×1920（版式见 `references/worlds.md`「竖屏」） |
| 时长 | 60 秒 | `new_film.py --dur 60`；有配乐时以 `beat.py` 取整到小节的长度为准 |
| 故事 | 由我挑一个最反常识、能核实的真实故事 | 第 1 步 |
| 外观 | A 鎏金（电影感暗金） | `--world A`；心理机制题材想要插画选 B，抽象概念选 C |
| BGM | 用户给文件就用，没给就合成 120 BPM | `engine/beat.py` 或 `engine/score.py` |

简报的节奏要求，在分镜表里逐条落实：

- **0–2 秒是反常识的钩子**：第一帧就有画面和大字（`K.headline`，第 0 帧满亮），不能是黑屏，不能先淡入。
- **顶部常驻一行钩子标题**（`K.hookBar`）：从第 0 帧到最后一帧都在，一句话说出全片的悬念。
- **每 10–15 秒一个转折、悬念或"你猜？"**：分镜表里标出来，60 秒至少四处；"你猜？"那一镜停住、出提示音（`ping`），下一镜揭晓。
- **结尾一句触动人心的话**：最后一屏是这句话 + 文献线索，不是总结。
- **每个场景都有前景、中景、背景三层和各自的动态**（`K.depth`），不是一张平面图上摆东西。

做法上和以前的区别（以前的规矩照旧有效，冲突时以这里为准）：

1. **事实先核，逐条列出**：先交一张事实表（每条：事实 / 出处 / 把握），再写分镜。
2. **分镜表带时间码，三列是画面 | 字幕 | 音效**，切点对小节线。
3. **声音先于画面定下来**：先跑 `beat.py`（用户的曲子）或定好 `meta.music` 跑 `score.py`（合成），拿到小节线再排分镜时间码。
4. **9 帧拼图自查至少两轮**（`render.py --sheet`，默认均匀 9 帧 3×3）：看文字遮挡、构图、曝光，改完重截，再渲全片。
5. **交付三样**：`renders/final.mp4`（H.264 + AAC，峰值限幅）、`renders/overview.jpg`（成片抽帧总览）、`<工程名>_source.zip`（`scripts/deliver.py` 一次出齐）。
6. **不停下来等确认**：简报说"直接交付"，就从头做到 mp4，每完成一个阶段用一两句话告诉用户进展（事实表 → 分镜表 → 配乐 → 最难一镜 → 拼图两轮 → 全片 → 混音 → 交付）。用户说"先给我看分镜"才停。遇到报错自己排查修复。

## 配图不是讲解

这个 skill 做过一条失败的《折叠》（讲蛋白质和 AlphaFold）：全片的主体是一串星点连成的折线。
字幕说"只换掉第 6 个，形状就变了，这就是镰刀型贫血"，折线换了个卷法、变成玫红色。
颜色、字体、节奏都像参考片，可观众从头到尾没见过蛋白质是个什么东西、错一个字母到底坏在哪。
那串星点换给任何一段文案都成立——它是配图。

重做以后，同一段内容是：镜头从血管里的红细胞钻进去，找到一串珠子；第 6 颗变了色；拉出来，细胞弯成了镰刀；
再钻进去，珠串卷成一团抓住氧分子；变色的那颗在表面成了黏点；一团粘一团连成长杆；长杆从里面把细胞顶弯。
两版的对照图是 `examples/fold_old_vs_new.jpg`，重做的成片在 `examples/fold_C/`。

**动手前先读 `references/visualization.md`。** 四条参考片逐句的"文案 → 屏上是什么 → 观众为什么懂"、六种画法、什么时候不画、
怎么给概念找形象、分镜表怎么写，都在那里。本文件只是流程。

交付物：一个工程目录（`storyboard.md` 分镜表 + `film.js` + 渲染出的 `renders/final.mp4`），加上事实表。

## 九条规矩

0. **只讲透一个故事。** 一条片一个最反常识的真实故事，从钩子讲到结尾一句；不把三个知识点拼成大杂烩。60 秒放不下的，删，不压缩。
1. **先找形象，再写文案。** 每个概念先找到一样外行认得的东西来演它；句子里要有屏上看得见的东西和动作。画不出来的句子，改句子。
2. **屏上的主体叫得出日常名字，而且长得像它本身。** 一串有光泽的珠子、一个中间凹下去的红细胞、一条带刻度的数轴、一句古诗。
   点、线、圈、柱子、方框不算；一个圆圈加一个标签也不算。
3. **句子里的动词，屏上真的做。** "砍掉一半"就盖住一半，"粘住"就真的卡上去。数是算出来的；示意的地方写明"示意"。
4. **先例子，后道理。** 名字、公式、结论，排在观众看过例子之后。第 0 秒就是钩子画面和大字；片名卡可有可无（顶部钩子行已经在做片名的事）。
5. **该画的画，该停的停。** 提问、命名、结论、引文、出处，不配新画面——参考片里大约每五句有一句是这样。
6. **一个世界、一把尺子、几样道具用到底。** 一个场景撑两句以上，每句只改一处；结尾回到开头的画面。
7. **没有人声，外观统一，画面现写，场景分三层。** 文案就是字幕，每句一眼读完；一条片一套色、字、画法，每种颜色全片一个意思。画面和代码是为这份文案现写的，不套模板，不搬别的片子里的东西。
8. **每个事实带出处。** 年份、人名、数字上屏；不加水印，不加署名。

## 改到自己满意为止

第一次渲出来的画面几乎都有毛病。这种片子是看着图改出来的，不是写完代码就完了的——`fold_C` 那 33 秒改了三轮才成片。

- **每做完一镜就截图看。** `--sheet` 看全局，`--stills` 看原尺寸，`--motion` 看转场。看的是图，不是代码。
- **看的时候当自己是第一次看的观众。** 遮住字幕和小字过三问：这是什么 / 它在干什么 / 我明白了什么。答得含糊就是没做好。
- **对着 `references/visualization.md` 第八节的表逐条查**：主体够不够大、认不认得出、发不发白、小字压没压在东西上、字幕区干不干净、转场说不说得清。
- **至少改两轮再给用户看。** 每一轮：把看到的毛病列出来 → 改 → 重截同样的时刻 → 确认改掉了、没改坏别的。还有毛病就接着改，不要带着自己都看得出的毛病交片。
- **拿参考片当尺子。** 把自己的静帧和 `examples/` 里的 look 图并排放，再对照 `references/visualization.md` 第八节的表。差一截，就还没做完。
- **交片时说实话。** 还不满意的地方、没做的东西、没完整看过的部分，直接列出来。

力气不多的时候（时间紧，或者想得不深），照下面做，质量也守得住：

1. **不跳步。** 每一步的过关标准逐条对，没过不往下走。尤其是第 2、3 步：没有形象和分镜表，后面改多少轮都救不回来。
2. **拿不准就查表。** 这一句该怎么演，去 `visualization.md` 第一节的四张表里找最像的一行，照它的画法做；该不该画，查第三节。
3. **画面现写，不套模板。** 文案不同，屏上的东西就不同，代码也不同。`examples/` 是看别人怎么把一份分镜表做出来的，不是零件库——别把那里的珠子、细胞、数轴搬进自己的片子，也别让自己的片子长成它的样子。能带走的只有做法：先截图再改，实心的东西画在底层，推拉用对数缩放。
4. **宁可少，不要糊。** 时间只够把三个概念做好，就只做三个；每一镜都认得出，比多讲两个概念重要。
5. **先做 30 秒。** 开头 30 秒过了三问、给用户看过，再铺全片。

## 流程

每一步后面是过关标准。没过就停在这一步改，不往下走。用户说"直接做"时，第 2、3 步的确认可以不等，但东西照样要写出来。

命令里的 `scripts/`、`engine/` 指本 skill 目录下的路径；工程目录建在用户自己的项目里。

### 0. 看清手里有什么

- **只有题目**：从第 1 步做起。
- **有文案**：照样过第 1、2 步。文案里画不出来的句子（里面没有东西、没有动作）要改；保留原文的意思、事实和说话的口气，改完给用户看改了哪些。
  句长和句数的标准见 `references/script.md`。
- **用户手里有一版做坏的**：先看那一版（截帧对着字幕看），重做同一段内容，交片时给一张新旧对照图。

### 1. 立题和事实表

写下：一句话论点；3–12 个概念的清单，每个概念用大白话写"要观众明白什么"和"外行卡在哪"。
再列事实表：每个年份、人名、数字的出处和把握程度。把握不足的去查，查不到就换例子。

过关：论点一口气说得完；每个概念你能不用术语讲给外行听。讲不出来的，先去把它弄懂——含糊的句子都是没弄懂的时候写出来的。

### 2. 找形象

这是决定片子好坏的一步，时间主要花在这里。照 `references/visualization.md` 第五节，对每个概念按顺序问：
它本身是个东西吗 / 是个过程吗 / 是个量吗 / 是观众脑子里的事吗 / 是条规律吗 / 都不是就上字。
找到以后再问：观众在生活里哪儿见过它；换一个尺度看是什么样；它坏了会怎样；怎么画才像它本身、从哪个认得的画面进场。
然后定全片的那一个形象、那一把尺子，和哪些东西会回场。

过关：
- 每个概念的形象叫得出日常名字，说得出它长什么样；
- 至少一半的概念找到了生活里的锚；
- 没有哪个形象换给别的文案也成立；
- 说得出全片哪一下最让人"哦——"。

这是给用户看方案的第一个时机。钩子给三个方向和一个推荐。

### 3. 文案和分镜表一起写

格式和自查在 `references/visualization.md` 第六节，例子在第七节。一句字幕一行，带时间码（起–止秒，切点对小节线）：画面（画法六种之一或"不画"；屏上是什么、在干什么；前 / 中 / 背景各是什么）| 字幕 | 音效，再加屏上的小字、观众明白了什么两列。表头先写：顶部钩子行那句话、0–2 秒的大字、每 10–15 秒的转折点各在第几秒、结尾那一句。
字幕的量和句式按 `references/script.md`。**没有分镜表不建工程。**

过关：
- 遮住字幕一列，只读"屏上是什么，在干什么"，看得出在讲什么；
- 每一句里的名词，屏上找得到；
- "不画"的大约占五分之一——一个都没有，是把结论也画了；占了一半，是没找到形象；
- 每个场景撑了两句以上，每句只改一处；
- 每一镜过得了三问：这是什么（日常的词）/ 它在干什么（一个动词）/ 观众明白了什么。

这是给用户看方案的第二个时机：把分镜表给他看。

### 4. 选外观，定声音

| 题目是 | 选 |
|---|---|
| 简报没指定，或要"电影感、暗金" | **A 鎏金**（默认） |
| 一个心理 / 行为机制，想要插画、角色和场景 | B 寓言 |
| 一个抽象概念或一个看不见的机制，拆成几个当场可演的小实验 | C 夜曲 |

三套的色、字、版式、常驻元素、片名卡、竖屏版式、声音都在 `references/worlds.md`。同时定下颜色的含义，全片不破例。

声音在建工程之前定，分镜表的切点要对小节线：

```bash
python engine/beat.py 曲子.mp3 60 --out <工程>/audio/beat.json     # 用户给了配乐：测 BPM、第一拍，给出建议片长、从哪截（乐句开头）、每条小节线、配乐变强的时刻
# 没给配乐：在 film.js 的 meta.music 里写 bpm（默认 120）、段落强弱 sections、揭晓 drop，建完工程后 render.py --events，再 python engine/score.py <工程>
```

最大的揭晓对到配乐变强的那一拍（`beat.py --hit 秒` 按这个挑起点；合成配乐写进 `drop`）。

### 5. 建工程，先做最难的一镜

```bash
python scripts/new_film.py <工程目录> --world A --dur 60   # 竖屏加 --portrait；要 3D 加 --three（先跑 python engine/get_fonts.py --three）
python engine/render.py <工程目录> --sheet            # 均匀 9 帧 3×3；--sheet 3 8 15 22 指定时刻
python engine/render.py <工程目录> --stills 5.9 18.1  # 原尺寸截几帧
python engine/render.py <工程目录> --motion 8.2 10.6  # 这段时间里取 12 帧拼一张，看转场
python engine/render.py <工程目录> --serve            # 浏览器预览
```

`new_film.py` 建出来的 `film.js` 只是能跑起来的骨架，里面一行画面都没有：没有现成的钩子、没有现成的图表。每一镜都照分镜表现写。
先填 `SUBS`，再把分镜表里**最难画的那一镜**做出来，截静帧。引擎的用法在 `references/engine.md`。`examples/` 可以翻，看的是别人怎么把一张分镜表变成画面，不是去找能搬的零件。
字体缺了跑 `python engine/get_fonts.py`。

过关：拿这张静帧，遮住字幕和小字，问"这是什么、它在干什么"——答得出来；缩到手机横屏大小还分得清；纵向 80%–95% 只有字幕；
对着 `visualization.md` 第八节的表查过一遍。答不出来就重画，或者回第 2 步换形象。第一版几乎不会过，改两三轮是正常的。

### 6. 前 30 秒

30 秒里讲得完多少就讲多少，不要为了"讲完"往里塞。一个道理硬压进 30 秒，每句都只能点到为止，画面跟不上，看起来就抽象。
宁可只讲一件事，让它在屏上从头到尾发生一遍（参考片的开头 30 秒也只讲了一件事：鸟丢下自己的蛋去孵假蛋）。

景别要变。同一个固定画面不要撑过三四句：全景交代在哪，中景看它做什么，近景看关键的那一下；该单独给一个画面的地方（一条规则、一次对比）就换一张画，别在原画面上叠东西。

```bash
python engine/render.py <工程目录> --clip 0 30 head
```

渲之前先用 `--motion` 把每个转场前后各抽一张拼图看：镜头怎么进、东西怎么变、有没有哪一帧说不清在干什么。有就改，改完再渲。

过关：字幕出现后 0.3 秒内屏上有动作；"哦——"之前有铺垫、之后停得住；场景之间是长出来的或者推拉过去的，不是硬切。
这是给用户看画面的时机。

### 7. 铺全片

一个概念一个函数；常驻元素和字幕在 `draw` 的最外层统一画。
每做完两三个概念，`--sheet` 拼一张自查：有没有东西伸进字幕区，有没有两样东西同时抢着动，相邻两段是不是长得一样，该回场的东西回来了没有。
长片按章拆文件（见 `engine.md`）。

```bash
python engine/render.py <工程目录> --det              # 同一帧渲两次必须一样
python engine/render.py <工程目录> --jobs 4           # 全片，4 路并行
```

### 8. 声音

- **合成配乐**：`render.py --events` → `score.py <工程>`（出 `audio/music.wav`）→ `audio.py <工程> --bgm <工程>/audio/music.wav 0`。
- **用户的配乐**：`audio.py <工程> --bgm 曲子.mp3 -8 --from <beat.json 里的 start>`，从乐句开头截，结尾自动淡出 2.5 秒。
- **音效**：`fr.sfx(时刻, 名字)` 登记，11-03 起多了 `hit`（重击：揭晓、落字）、`whoosh`（呼啸：转场、推拉）、`ping`（提示音："你猜？"、数字跳出）。混音最后过限幅，峰值不过 -1 dBFS。
- 以下是原来按外观分的写法，仍然适用：
- **C**：`film.js` 里用 `fr.sfx(时刻, 名字)` 登记事件（每一下变化一声、推拉时的上滑音、落定时的低音、提问那一镜不出声），然后
  `python engine/render.py <工程> --events && python engine/audio.py <工程>`。
- **B**：用户给一首配乐，`python engine/audio.py <工程> --bgm 曲子.mp3 -8`。先量配乐的速度，把每段的开头对到小节线上，
  最大的那次揭晓对到配乐重新进入的那一拍。用户没给配乐就说明白：成片目前只有事件音，等配乐。

### 9. 终检和交付

```bash
python scripts/deliver.py <工程目录>      # 查规格（H.264 / AAC / 30fps）+ 成片抽 12 帧拼 renders/overview.jpg + 打包 <工程名>_source.zip
```

看 `overview.jpg`，再做三遍：

1. **静音、遮住字幕看一遍。** 每一段在讲什么，看得出来吗？
2. **只读字幕一遍。** 通顺吗？有没有哪句里的名词，屏上找不到？
3. **对照下面的门槛。**

| | 门槛 |
|---|---|
| 讲解 | 成片和分镜表对得上；抽五镜过三问都答得出；没有只是配图的画面；屏上的数前后对得上；尺子和道具回过场 |
| 画与不画 | 提问、命名、结论没有硬配图；也没有连着几句画面不变 |
| 结构 | 第 0 帧有画面和大字；顶部钩子行全程都在；每 10–15 秒一个转折 /"你猜？"；结尾回到开头的画面；最后一屏是触动人心的一句 + 文献 |
| 字幕 | 每句一行；B 停留约 3 秒、C 约 3–5 秒；一句最多染一处颜色 |
| 画面 | 字幕区没有别的东西；任何一刻只有一个主体在动；一镜最多一条小字；颜色含义全片一致 |
| 节奏 | 没有硬切；主体出完之后停住让人读；每 20–30 秒一段无字幕的纯画面 |
| 事实 | 屏上每个数字和事实表一致；每个概念有出处；示意的地方写明了 |
| 声音 | 切点、揭晓落在小节线上；配乐是完整乐句，结尾淡出，不拦腰截断；峰值不爆 |
| 技术 | `--det` 通过；1920×1080 或 1080×1920，30fps；H.264 + AAC；没有水印和署名；交付了 mp4、总览图、源码 zip |

不合格的时间点列出来，改完只重渲那一段（`--clip`）确认，再渲全片。交片时把没做到的地方直说，包括成片有没有完整看过。
