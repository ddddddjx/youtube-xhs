## 一、版式（从上往下）

| 位置 | 做法 |
|---|---|
| 标题 | `栏目名｜主体 + 事件：判断一，判断二`。「深度」「ZPedia」是栏目；冒号后两个短判断，第一个是结论（增收不增利），第二个是更大的意义（具身智能开始为模型和算力买单） |
| 列表封面 | 红黑撞色海报插画：红底、撕纸白条、主体（机器人 / 指纹）+ 超大黑体品牌字。列表里图和标题说的是同一个主体 |
| 正文顶部 | 一条品牌横幅（红底 + 白色 Logo），下面再放一次封面海报 |
| 导语 | 一句话，把整篇判断说完：「把……两种速度摆在了一起：A，B 却在减少」 |
| 第二段 | 时间 + 事件 + 三四个关键数，最后一句给方向（「它正在更快地把这些钱投入下一轮竞争」） |
| 第三段 | 「方向则比较明确」：公司自己的表态 → 「这揭示了 X 所处的位置」→ 一句克制的判断 |
| 小节 | 灰色超大数字 `01` `02` `03` + 红色粗体小标题，小标题本身就是这一节的结论句（「研发加速，宇树要把硬件优势延伸到 AI」） |
| 数据 | 表格做成图：深灰底、细分隔线、首列加粗、数字右对齐；表下灰色斜体「图表备注：口径、哪个数是倒算的」 |
| 配图 | 原始资料图（模型结构图）+ 下方灰色斜体图注 |
| 正文 | 中性第三人称，不出现「我」；一段一个意思；每段最后一句往往是「这意味着」式的推算或解释 |

## 二、叙事结构

1. **先给结论，再给数，最后给位置**：导语一句判断 → 第二段把数摆出来 → 第三段说这家公司处在什么阶段。读者读完前三段，就知道全文要证明什么。
2. **每节先摆事实，再自己算一步**：「每实现 100 元收入，就有约 19 元对应研发费用」「新增研发和销售费用合计约 3.27 亿元，已经超过新增毛利」。不是转述公告，是替读者把账算出来。
3. **口径写清楚**：表下备注说明哪个数是倒算、哪个是按什么口径计算的。可信度来自这里。
4. **小标题就是结论**：只看小标题也能读懂全文。

## 三、我们能学的 / 不学的

能学（11-02 第一次用在 `发布/2026-11-02_claude-code-team/公众号版/`）：
- 标题「栏目｜主体：判断一，判断二」
- 导语一句判断 + 第二段事实锚 + 第三段位置
- `01` 编号 + 结论句小标题（prep_wechat.py 新增 `--style zf`）。**颜色不学它的红**：用户 11-02 定本号主题色是头像黄 #FFE600，编号块黄底黑字、小标题黑色、封面黄底
- 对比和数据做成表格图，表下斜体「图表备注」写口径
- 中性编辑部口吻，只在结尾留一句判断

不学：
- 它的红黑插画是 AI 生成的海报，我们用素材截图 + 代码排版做撞色海报（本号用黄黑），不编造画面
- 品牌横幅先不做，等用户定公众号的视觉
- 这是财经号的数据密度，AI 对谈稿没那么多数，不硬凑百分比

待用户定：公众号以后是否固定这套版式（栏目名用什么、横幅要不要）。
