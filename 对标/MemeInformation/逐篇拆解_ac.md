## 《千问生图Skill，到底藏了多少玩法》
- 类型：实测（教程型，用千问「工作助理」的技能做一套旅行图文 + 装外部 Skill 修图）
- 叙述者身份：做小红书图文的内容创作者（「我正好想做一篇户外旅行图文」），身份让实测有真实需求，读者代入「我也要做封面」
- 标题拆解：「产品名+功能名，到底藏了多少玩法」——品牌前置、「到底」口语追问、「藏了」暗示有隐藏技巧；问题式标题，正文用 3 类玩法（封面 / 配图 / 外部 Skill）作答
- 开头：一句交代动机 + 路线图（「先做封面和正文组图，再……」），第二段直接「成品先放在前面」，先给 5 张成品图勾住，再讲步骤
- 骨架：动机+路线 → 成品图墙 → 步骤1 选技能出封面（截图+完整提示词）→ 评价「可以直接用」→ 步骤2 同主题补 2 张配图（提示词+结果）→ 小瑕疵「略有点紧绷」→ 进阶：装外部 Skill 三步法 → 成品 → 换一个 Skill 同样三步 → 泛化结论「先去看看有没有现成技能」
- 论证与证据：全程亲测截图，带①②③④序号标注操作位置；提示词原文全贴；每步后给一句效果评价
- 品牌 / 产品怎么进入：第 1 句就进入，整篇是产品教程，像商业合作；不硬靠「自己的真实选题」做载体，且承认缺点（人物「略有点紧绷」）
- 节奏与语言：短段、流程化（「第一步/第二步/第三步」），口语克制；评价句朴素（「作为封面已经可以直接用」）
- 结尾：从功能拔到方法论——「能直接复用的方法，就没必要每次都从头摸索」
- 最值得学：①成品前置，先给结果图再讲步骤；②截图上打序号标注 + 可复制的完整提示词，让读者照着做

## 《复杂提示词，正在被Agent公司终结....》
- 类型：实测 + 产品推荐（Libtv 视频 Agent 的 4 个功能）
- 叙述者身份：做 AI 短剧的团队负责人（「最近我们团队在做AI短剧」），提供真实痛点和自家作品《她记得明天》作案例
- 标题拆解：「X，正在被 Y 终结....」趋势判断式，拟人化动词「终结」制造危机感，省略号拖尾留悬念；不点产品名，品牌藏在正文；标题是结论（门槛降低），正文到最后一段才回扣「降低……写复杂且精确的提示词」
- 开头：从团队遇到的问题起笔，列 2 条痛点（「脸基本上没有特色」「播放量破千亿但没人记得住角色」），再给判断「真正能拉开差距的，是……人脸」
- 骨架：团队痛点 ×2 → 行业判断 → 「刚好」试了 Libtv → 功能1 情绪调节（以前 vs 现在 + 配图 + 25 个表情）→ 自家短剧用了、观众反馈 → 功能2 虚拟角色库（23 个角色）→ 功能3 3D 导演台（擂台搏击例）→ 功能4 AI 故事板（自家片子十个分镜）→ 缺点：token 消耗不低 → 总结「思路蛮不错」
- 论证与证据：自家作品案例、「以前……现在……」对比、功能数字（25 个表情、23 个角色）、流程截图
- 品牌 / 产品怎么进入：第 1 页中段用「刚好这段时间我也试了很多视频agent产品」自然带出，明显商业合作；用团队真实需求做前置、每个功能都挂「以前多麻烦」，并主动说缺点「咱说句实话……token消耗不低」来降硬度
- 节奏与语言：编号列表 1-4 功能；口语「咱说句实话」「蛮不错」；每个功能 = 痛点一句 + 功能一句 + 效果一句
- 结尾：温和总结「所以我觉得产品整体的思路都蛮不错的」
- 最值得学：①用「我们团队在做 X 遇到的问题」开局，把产品功能当成对自家痛点的解法；②商业内容里插一句实话缺点，增加可信度

## 《大模型会越来越卷怎么更快输出......》
- 类型：论文解读（阶跃星辰参与的 JETSPEC 投机解码论文）
- 叙述者身份：做 Agent 产品的人（「最近做 Agent产品的时候」），把论文问题落到产品体感「让用户等得太久」
- 标题拆解：趋势判断句，口语「会越来越卷」，六个点省略号；标题就是结尾最后一句的缩写，结论型；不带论文名和公司名
- 开头：情绪化抱怨起笔「大模型很多时候干活干得太慢了！」，再用一 token 一 token 的通俗解释点出原因
- 骨架：做产品的抱怨 → 原理（自回归）→ Agent 场景放大问题 → 「刚好发现」论文 → 投机解码通俗解释 → 两个关键变量 → scaling ceiling 图 → 旧方法两类及缺陷 → 论文里的「given told that」例子 → 核心创新（因果并行 draft head）→ 「换个咱们更好懂的说法」候选树 → 工程巧思 → 实验数字 → vLLM 实测 → 适用边界 → 与 DeepSeek DSpark 对照 → 行业趋势判断 → 回扣标题
- 论证与证据：论文截图、图表、具体倍数（9.64x、553.3 TPS 提升 4.33x）、同类论文对照、论文中的反例
- 品牌 / 产品怎么进入：第 2 页「刚好发现了一篇特别有意思的论文」，公司名放在「阶跃星辰参与提出的」定语里，淡化合作感；可能是商业合作但以论文科普外壳呈现
- 节奏与语言：一句一段，术语后立刻「也就是」「可以简单理解成」「换个咱们更好懂的说法」翻译；自问转折「但这里有个很现实的问题」
- 结尾：趋势句回扣标题「接下来，大模型可能会越来越卷怎么更快输出…」
- 最值得学：①硬核论文用「我做产品的痛点」进场，每个术语后跟一句大白话翻译；②结尾拉一个同类工作对照，升到行业趋势

## 《大模型终于能进入企业生产语境了》
- 类型：活动见闻（火山 Force 大会，未到场）+ 轻实测
- 叙述者身份：没被邀请的行业观察者 + 内测用户，自嘲身份拉近距离，内测资格提供一手体感
- 标题拆解：「终于」情绪词表达等待已久的肯定，判断式结论标题；不带品牌名
- 开头：自嘲梗三连——「今天我本来应该去火山的 Force 大会，但是我没有去」「为什么呢？」「大概是他们忘记邀请我了」，用幽默留人
- 骨架：没去大会的自嘲 → 朋友传来前线消息 → 抛核心问题「模型到底能不能真的拿来干活」→ 个人复杂感受（跑分高但放进工作流会露馅）→ 看模型标准：能否从头做到尾 → Seedance 2.0 以前 vs 现在 → 判断「能进入企业生产语境」→ Seed 2.1 内测体感 → 大会 case：RTL 连跑十几小时 → 视频自动剪辑 → 上线渠道 → 价格 → 个人判断标准
- 论证与证据：朋友消息、内测体感、大会 case 图表、价格数字（输入 6 元、输出 30 元）
- 品牌 / 产品怎么进入：第 1 页第 1 句就点火山，但以「没被邀请」的反商业姿态进入；价格用「比较 PDD」口语化
- 节奏与语言：一句一段，「你说它没变强吧，也不对」式自问自答；「说句大实话」
- 结尾：给出自己的评价标准——「能被反复打开，才是真的有用」
- 最值得学：①发布会稿用自嘲开头（没被邀请）去掉通稿味；②结尾不下结论而给「我怎么判断一个模型好用」的标准，留观察窗口

## 《字节的AI办公应用，终于要合成一个了》
- 类型：行业观察 / 公司动态解读（TRAE、扣子并入豆包）
- 叙述者身份：刚实测过豆包「工作任务」的用户，身份把新闻和自己的实测连起来
- 标题拆解：「公司的 X，终于要合成一个了」，「终于」+口语「合成一个」，新闻事实型；品牌前置
- 开头：「前几天刚实测完……字节又……往前推了一步」，用个人时间线接新闻；随后「我第一反应是……是不是都没了？」替读者问
- 骨架：接上次实测 → 新闻事实 → 第一反应疑问 → 官方回应 → 豆包工作即将上线 → 近一周密集功能 → 回放自己的实测（团建报名表→Excel→PPT，30 分钟）→ 手机改 PPT 12 分多钟 → 背景：能力原来分散在哪 → 飞书整合 → CEO 全员会「粗主干」 → 判断
- 论证与证据：报道信息、官方回应、自己的实测截图表格、耗时对比（人要半天 vs 30 分钟）、CEO 原话
- 品牌 / 产品怎么进入：全篇是字节新闻；自己的实测被嵌在新闻里做证据，不像硬广
- 节奏与语言：新闻句偏书面，个人句口语（「少说也要半天」）
- 结尾：一句趋势判断「聊天已经是豆包最普及的入口，下一步则是处理……工作」
- 最值得学：①新闻稿里插入自己之前的实测回放，让「整合」有可感知的例子；②「我第一反应是……」替读者提出担忧再解答

- 开头：第 1 页直接放外网推文截图做证据，第 2 页「外网刚爆出来的料」口语爆料式
- 骨架：外网截图 → 爆料事实 → 数据排名 → 转折「很多人只盯着排名看热闹，真正值得关注的是……」→ 卡脖子背景 → 5-6 万张国产卡 → 判断「含金量很高」→ 排行榜截图
- 论证与证据：推特截图、OpenRouter 排名表（6.82T tokens）、「根据之前的信息」的算力数字

- 标题拆解：「很多 X，其实只是 Y」反常识判断，「其实」揭穿；标题是正文第 6 页的原句，结论型；不带品牌
- 开头：热点作品起笔「《丧尸清道夫》最近刷屏」，随即抛问题「如何让模型理解自己的表达？」，再给震撼数字「单人、10天、3000元成本」
- 骨架：刷屏作品 + 数字 → 个人感受（竞争重点转移）→ 过去 vs 现在能力 → 矛盾：被 Prompt 困住「人却越来越像在给工具打工」→ 转机：模型能承接视听语言 → 引出火山 Vibe Creating → 解释分工 → 高质量 Prompt 要说清几个问题 → 标题句 → 技术指令 vs 感受描述例子 → 自问「是不是想说 Prompt 没有价值了？」→ 边界（商业定制仍需精确控制）→ 趋势判断 → 普通写法 vs Vibe 写法完整对比
- 论证与证据：热点案例数字、「缓慢推轨镜头」vs「视线缓缓靠近，带来压迫感」对照、完整 Prompt 前后对照（带括号标注结构）
- 品牌 / 产品怎么进入：第 4 页后半「火山引擎最近提出了一个概念」，以概念而非产品进入，作者「大概理解了一下，觉得……有价值」，软性合作
- 节奏与语言：金句型对仗（「前者是在告诉模型怎么动，后者是在告诉模型为什么这样动」）；自问自答
- 结尾：用一组可复制的 Prompt 对比例子收，实用落地
- 最值得学：①金句对仗 + 前后对照例子，把抽象观点变可操作；②把正文里最反常识的一句直接做标题

- 标题拆解：「很多人不知道 X 和 Y 的区别」信息差句式，点名品牌；标题只对应前 2 页科普，正文主体其实是 4 条用法窍门——标题是钩子，不是全文结论
- 开头：「最近我发现一个挺有意思的现象」——开发者圈叫 Qwen、普通人叫千问，用两个圈层的认知差起笔
- 骨架：现象（两个名字）→ 解释模型 vs App → 组织架构（Token Foundry / 千问事业部）→ 一句话总结分工 → 个人使用经历 → 发现：很多人不会说清需求 → 窍门1 别当搜索框（高铁票前后对比 + 截图）→ 窍门2 需求别只说一半（杭州酒店、PPT）→ 窍门3 让它先筛选你确认（北京展会截图）→ 窍门4 存成固定指令（会议纪要）→ 总结三类功能 + 三件事 → 从小事开始

- 节奏与语言：编号小标题 + 情景例子；句式「与其问……不如说……」
- 结尾：给行动起点——「可以先从一份会议纪要、一次出行规划……开始」
- 最值得学：①用「两个名字/两个圈层」的信息差做标题入口，再转实用技巧；②每条技巧都给「普通问法 vs 好问法」可直接抄的句子

- 类型：其他（社区推广：智元 AIMA 开放平台社区 + 首月创作者活动）
- 叙述者身份：逛过 WRC 的行业关注者、社区浏览者
- 标题拆解：疑问句「X 圈的大佬都在关注什么？」，借「大佬」制造圈层好奇；正文只用「看到了一些熟悉的名字」一句呼应，标题与正文核心（社区入口 + 活动）有落差，属钩子型
- 开头：「前段时间逛完WRC，我有个很直观的感受：机器人开始认真找工作了」——拟人化判断
- 骨架：WRC 感受 → 场景变化 → Demo 离上岗有距离 → 经验散落 → 两个设问（去哪看项目、去哪找同行）→ 引出社区 → 内容好逛（举例）→ 熟悉的名字 → 分享的价值（少踩坑、降低信息差）→ 个人作品记录 → 入口 → 首月活动奖品 → 号召去逛
- 论证与证据：社区截图、帖子示例、奖品清单
- 品牌 / 产品怎么进入：第 2 页「最近我逛了智元AIMA开放平台社区，觉得它刚好提供了这样一个入口」，典型推广；先用 WRC 见闻 + 两个设问把需求立住再给答案
- 节奏与语言：平实，排比「会开发的人……正在学习的人……平时关注行业的人……」
- 结尾：号召 + 降低门槛——「认真记录一次学习……都算是进入这个行业的一步」
- 最值得学：①推广前先用两个「去哪里……？」设问制造需求空位，再把产品填进去；②拟人化开头判断（「机器人开始认真找工作了」）

## 本组共性
（20 篇，其中《我一开始不理解，为什么有人跳槽去得物》仅 1 张标题图，正文统计按 19 篇计）

2. 标题句式（出现篇数）
   - 趋势进行时「X，正在……」「开始……了」：3 篇（复杂提示词正在被终结、打字正在拖慢、AI大赛开始抢普通人）

   - 「终于」：2 篇；「很多人不知道」：2 篇；「很多 X，其实只是 Y」反常识：1 篇
   - 省略号拖尾「....」「......」：2 篇；小红书情绪体「救命，……也太爽了」：1 篇；场景意象句：1 篇（往杭州移动了一格）
   - 品牌名进标题的只有约 8 篇，且常放在「我让 X」「X 的 Y」结构里；约一半标题完全不带品牌，只写判断或场景
   - 标题 = 正文原句（常为第一句或中段顿悟句）：至少 5 篇（打字、专业Prompt、杭州、更快输出、终结提示词结尾回扣）

3. 开头类型
   - 身边人 / 自己团队的具体问题或对话：5 篇（团队做短剧、朋友聊企业落地、学弟问 offer、朋友饭局、自己的突发技术分享）
   - 自嘲 / 糗事：2 篇（没被邀请去大会、错过老东家股票）
   - 现场 / 行程场景：4 篇（成都科幻馆外火锅店、去杭州的行程、听完分享停了好一会儿、逛完 WRC）
   - 新闻事实直陈：3 篇（字节整合、美团模型爆料、智谱融资）
   - 个人抱怨 / 感受判断：2 篇（模型太慢了！、工作崩溃在第一步）
   - 热点作品 / 现象：2 篇（丧尸清道夫刷屏、Qwen 与千问的认知差）；名人海报误会：1 篇；成品前置：1 篇
   - 共性：第一句几乎都带「最近 / 昨天 / 前几天 / 上周」时间锚点（约 14 篇），马上交代「我」在场

4. 骨架模板（高频）
   - 实测模板：个人真实需求/痛点 →「刚好/这也是我试 X 的原因」→ case1（截图 + 提示词原文）→ 小翻车或小瑕疵 → case2 加码 → 原理一句大白话 → 缺点坦白 → 方法论金句
   - 活动模板：现场细节/场景 → 最打动我的一句话（原话引用）→「确实」+ 生活类比 → 数据 → 按链路拆 3–4 件事 → 反差点 → 我的判断 → 回到开头场景
   - 观点模板：热点/朋友的话 → 抛问题 → 过去 vs 现在 → 矛盾 → 概念/大佬观点 → 自问「你可能会问……」→ 边界 → 对照例子
   - 「以前……现在……」对比出现在约 8 篇

5. 品牌植入模式
   - 用「刚好 / 正好 / 今天正好看到 / 刚好对得上 / 刚好提供了这样一个入口」接入：约 7 篇
   - 产品在第 2–3 页（或全文 1/3 处）进入，前面先立痛点：约 9 篇；半篇后才进（表妹校招）：1 篇
   - 借第三方之口：大佬采访（朱啸虎）、高管原话（刘逍）、科学家分享（黄用韬）、朋友/司机：约 5 篇
   - 主动写缺点或翻车以增信：6 篇（人物略紧绷、token 消耗不低、Kimi 翻车、可用底稿、tree budget 不宜过大、0 门槛不是随便交想法）
   - 名字常做定语淡化（「阶跃星辰参与提出的 JETSPEC」「蚂蚁灵波首席数据科学家」）

6. 结尾类型
   - 意象 / 比喻金句：5 篇（铺了十几年的路、通向AGI的盘缠、有人真的走进去坐下来、拿回判断权、让真实世界成为训练场）

   - 个人判断标准：2 篇（能被反复打开才有用、时间不该花在打字上）
   - 回扣标题的趋势句：2 篇；具体个人行动：1 篇（停掉投研会员）；温和总结：2 篇
   - 共性：不写「关注我 / 下期见」，停在一句判断或一个动作上

7. 高频表达 / 口头禅
   - 「我觉得 / 我一直觉得 / 我更关心」：几乎每篇
   - 大白话翻译器：「说人话就是」「说得简单一点」「换个咱们更好懂的说法」「简单说」「可以简单理解成」：5 篇
