## 他怎么写

**1. 标题是一句平常话，用句号结尾。** 「我已经蹬完了 5 亿……」「感觉 AI 可以……」「头一回这么深刻的理解了……」：第一人称的感受或者动作，没有逗号两段式，也没有反问。句号让标题读起来像在跟人说话，不像在做广告。

**2. 第一段直接讲事实和数字，不交代信源。** 「OpenCode 上最近有个叫 Space Bunny 的匿名模型特别火。截至我写这篇文章，它已经连续五天排到模型使用总榜的第一。」第二段马上接自己的动作和一个大数字：「我已经蹬完了将近 5 亿 Token」。没有「今天刷到」。

**3. 「我」是一个完整的人，不只是一个职业身份。** 喜欢银杏，每年秋天捡叶子夹在书里；是山西人，喜欢古建；给孩子做过电子画册；有一份心愿 TodoList，用语音输入法记灵感；中秋假期用手机远程遥控 Claude Code，「像钓鱼一样」。这些细节和 AI 没关系，正是它们让读者觉得屏幕那边有个人。

**4. 话里留着口语毛边。** 「不知道咯。」「反正免费」「这玩意」「咱也不说追平谁谁谁吧」「还行还行。」「可真是中国的上海啊」。比喻都来自日常生活：领鸡蛋（免费 Token）、结婚过日子（选模型）、钓鱼（远程跑 agent）、有人免费帮你干一个月的活（免费模型）。

**5. 判断说得随意，猜就直说是猜。** 「我感觉大概率还是国内模型」→ 用排除法推一遍 → 「不知道咯。」。局限也照直说：「中间肯定也会犯错」「有时候也会在一些简单的任务上过度思考」。

**6. 段落是两到四行的一小段，靠「比如 / 所以 / 毕竟 / 像」往下接。** 一段一般有两三句，读起来是一口气说下来的，几乎没有单句成段的金句，也没有刻意埋的钩子。页末断在哪里全看篇幅（RSI 那篇断在「……迭代与优化 / 的循环。」）。

**7. 结构跟着「我做了什么」走，不搭框架。** Space Bunny 那篇：它是什么 → 猜是谁家的 → 性能感受 → 第一个 Case → 第二个 Case → 我的习惯 → 第三个 Case → 整体评价。没有三点，没有方法论小结，也没有单独的「领取物」。

**8. 像在给人演示屏幕。** 「我截个图，大家看右上角的电话按钮」「大家可以仔细看一下风铃」「大家着重看下第一点」「大家可以查查」。图出现之前，先告诉读者该看图上哪里。

**9. 技术解释用「粗略地理解成」。** 「可以很粗略地理解成，大部分层只关注附近的信息，每 5 层再安排一层，从全部历史里筛选出最重要的信息。」先承认是简化，再讲人话。参数直接用「1、2、3、4」列出来。

**10. 结尾往下收。** 「整体来说，还行还行。」「我的话肯定有，因为这个 TodoList 已经攒了不少东西。」没有回扣金句，没有升华。

## 我们 10-03 那篇（Harness 稿）和他差在哪

| | 小盖 | 我们 |
|---|---|---|
| 标题 | 「我已经蹬完了 5 亿……。」一句平常话 | 「你的Harness配好了，检查器还会量错」，句式是搭出来的 |
| 第一段 | 事实 + 数字，然后是我做了什么 | 「今天我刷到 @beamnxw……」，先交代信源 |
| 我 | 爱好、家乡、孩子、假期在干什么 | 只有「读到的人」，外加一个检查脚本 |
| 段落 | 两到四行，句子之间有连接词 | 大量一句一段，「说人话就是」「最硬的一句在」这类搭桥句 |
| 比喻 | 领鸡蛋、结婚、钓鱼，生活里随手拿的 | 「一把新尺子」「长成检查器喜欢的形状」，是写出来的修辞 |

| 结尾 | 「还行还行。」 | 回扣 47 个赞，一看就是设计过的 |

一句话：他像在跟朋友聊这几天干了什么，我们像在写一篇论证。读者说的「AI 味」，大半来自后者。

## 能学的（不违反账号规则）

1. 标题试一种平常话 + 句号的写法，和现有句式做 A/B：「头一回看懂 Agent harness 是什么。」「我的检查脚本全过了，评论区还是不买账。」
2. 第一段先讲事实和数字，信源放到第二、三段，一句话带过。
3. 一段写两三句，用比如、所以、毕竟往下接。单句成段一篇最多两三处。
4. 比喻只从日常生活里拿（买菜、带孩子、考试、上班通勤），不写「一把尺子」这类修辞。
5. 放图之前先告诉读者看哪里：「大家看这张表最后一行」。
6. 拿不准的直接说拿不准：「我猜……不知道对不对」。
7. 结尾可以往下收，一句评价就停，不一定要回扣。
8. 「我」要变成一个完整的人：需要用户补生活细节（爱好、城市、这周在干什么、家里人、手机上常开的 App），写进经历库。**这一条最关键，也是我们最缺的。**

## 不能学的

- 他的经历（5 亿 Token、山西人、孩子的电子画册、银杏）：用户没有，不借。
- 「强烈推荐」「最前沿 / 最激进」「比 90% 的导游都专业」：极限词，账号规则禁用。
- 软广痕迹（豆包「完全免费」那篇读起来像合作稿）：我们不放任何售卖信息。
- 他不放领取物；我们的提示词照样放，只是写得像随手递过去（「这段可以直接贴在派活的最后」），不单独搞成一节方法论；不写「我平时都这么用」，除非经历库里有。

# 第二批（10-03 补）：Jev 稿和 Kimi FDE 稿，活人感不靠生活细节也能成立

第一批拆出来的结论是「我要变成一个完整的人」，这条我们最缺。第二批两篇里几乎没有银杏、孩子、山西这些东西，「我」只做了三件事：上手跑了 case、看了访谈、越来越觉得。可它们照样不像 AI 写的。差别全在讲法上，下面每一条都是我们这周就能用的。

## 两篇的数据说明什么

| | Jev（知识编号稿） | Kimi FDE（站队稿） |
|---|---|---|
| 赞 / 藏 / 评 | 220 / 203 / 6 | 927 / 574 / 85 |
| 题 | 一个新模型的训练范式 | 开源 vs 闭源、Kimi vs OpenAI |
| 标题 | 平常话 + 句号，自我设定「言简意赅」 | 对比句 + 句号，「和 X 完全不一样」 |
| 第一句 | 意图：「想言简意赅再写写我对 Jev 的理解」 | 判断：「越来越觉得 OpenAI 和 Anthropic 很难垄断智能行业」 |

知识稿收藏和赞一样多，评论几乎没有；站队稿赞是四倍，评论是十四倍。**要曝光，题目得有两边可站；要收藏，正文得是能按编号查的知识。** 一篇稿最好两样都占：对比句当标题，编号知识当正文。

## 他这两篇怎么写（第一批没拆到的）

**11. 第一句直接是判断或意图，信源退到第二句之后。** Kimi 稿：「越来越觉得 OpenAI 和 Anthropic 很难垄断智能行业。」第二句才是事实加专名加数字：「前段时间，美国法律 AI 独角兽 Harvey 用 Kimi K3 训练出了自己的专有模型。」第三句推理：「因为如果一家垂类 AI 公司……那它就没必要……」。Jev 稿第一段就把反差放在段尾：「很多人觉得 Jev 就是之前我们熟悉的分类模型，其实根本不是这么回事。」首屏的顺序是：判断 → 事实 → 为什么 → 反差，没有「刷到一篇长文」。

**12. 知识稿的骨架是编号 1、2、3……9，每个编号开头那句自己就是一个判断。** 「1、如果只看训练范式，LLM 这几年真正的关键节点大概有三个。」「5、理解了这个训练逻辑，就会知道，Jev 根本不是小模型，也不是分类模型。」「7、Jev 和目前我们熟知的 LLM 模型是互补的关系。」编号下面再跟一到三小段支撑。读者可以只读九个编号句就拿走全部结论，这就是收藏的理由。这和我们黑名单里的「理由有两个。一是……二是……」不是一回事：他的编号后面跟的是完整的判断句，不是「原因一、原因二」的提纲。

**13. 先用读者已经知道的东西锚新东西。** 讲 RLCD 之前，先把预训练、RLHF、RLVR 三个已知节点各用一段讲一遍，再说「Jev 的逻辑是也许还有第三种后训练方向」。讲 Kimi 的 FDE 之前，先讲 Palantir 怎么做 FDE、OpenAI 和 Anthropic 怎么自建团队，再一句「但 Kimi 这次完全反其道而行」。新概念永远是已知清单上的「第 N+1 个」。

**14. 平行句式做对比。** 「RLHF 的北极星指标是 instruction following……RLVR 的北极星指标是 verifiable outcome……Jev 使用的训练方法叫 RLCD，它的目标是让模型输出经过校准的决策概率。」三段同一个句式，读者不用理解术语也看得出第三个和前两个不一样。「之前的软件主要是 Logic + Data，未来的软件会越来越接近 Logic + Data + Intelligence。」也是同一招。

**15. 概念的名字放在解释后面。** 先讲「输入不一定非得组织成人能读懂的 Prompt，输出也没必要再生成一段漂亮的自然语言……交给 if、switch、排序和阈值判断继续执行」，然后才是「所以 Jev 创始人一直强调一个词，Machine Native。」先讲完一串「云厂商提供算力……行业服务商负责落地……」，然后「这就是生态。」名字是收束，不是开头。读者先懂了事，再拿到词，词就记得住。

**16. 同一组例子从头用到尾。** Jev 稿的例子只有三个：邮件有多紧急、客户流失风险多高、工单该分到哪个部门。第 7 点用、第 8 点的伪代码用、第 9 点的 Choice / Noul / Score 还是用。Kimi 稿的例子也只有中软、亚信、AWS、Fireworks。例子少，读者才记得住。

**17. 换一群读者再讲一遍。** 「8、再解释一下 Jev 到底怎么用，程序员可能会更容易理解。」然后是四行伪代码：`urgency = AI.score(email)` / `if urgency > 0.8: notify_manager()`。前面七点是给看概念的人，第八点是给写代码的人，同一件事讲两遍，两群人都碰到了。我们的两群读者（AI 技术类男性、个人成长类女性）正好需要这一招：每篇一次「换个说法」。

**18. 替读者把反驳说出来，再用事实接住。** 「9、有人可能会说，这些事情用一个小模型不也能做吗？LLM 早就可以理解自然语言了。」「确实，单独做一次判断并不难。真正的挑战是，怎么把这种判断变成足够稳定、可校准、可验证的程序能力。」「大家应该都经历过，这种方式偶尔就会冒出一些很奇怪的判断。」这是让步再转折，但让步的那句带着事实（「单独做一次判断并不难」），反驳的是读者真会问的问题，不是在给自己的立场留后路。和 10-02 被骂的「他可能是对的。但今天我会……」区别就在这。

**19. 回指自己之前写过的稿子。** 「具体为什么不一样，前几篇文章我已经详细写了。」「想言简意赅再写写我对 Jev 的理解。」一个「再」字，读者就知道这个号在持续追这件事，这是关注理由，比「求关注」强。我们不预告下一期，但可以回指已经发出去的那篇。

**20. 截图上画红框，文字先说结论，图再证明。** 「但 Kimi 这次完全反其道而行。」下面是官宣截图，「Kimi 选择以开放合作的方式推进企业级落地」这一句框了红框。AWS 那张也是，「Moonshot AI 推出的 Kimi K3 已在 Amazon Bedrock」框出来。读者不用读整张图。

**21. 单句段他也用，但只有三种。** 带态度的判断：「这就是开源的优势。OpenAI 根本没办法这么玩。」说话人的动作：「我展开说下。」给刚讲完的一串事实起名：「这就是生态。」没有一句是飘着的金句（「规矩得先立在文字上。」那种）。Kimi 稿 1400 字里有七八处单句段，照样不像 AI，因为每一句都接着上文的具体内容。

**22. 毒舌对着公司和现象，用强否定词。** 「其实根本不是这么回事」「完全反其道而行」「OpenAI 根本没办法这么玩」「商业模式完全不一样」。不对着人，也不加「哈哈」。

**23. 结尾先降温再给一句温和的判断，或者停在功能说明上。** Kimi：「没有谁对谁错。我只是觉得，当模型足够强之后，也可以把开源当做一个商业优势。」Jev：最后一段讲 Score 可以拿来排序或者设阈值，讲完就停。两篇都没有回扣标题，没有升华。

**24. 字体是衬线（宋体），不是黑体。** 两篇的正文都是宋体，在信息流里一眼就是「一个人认真写的长文」，和满屏黑体大字的营销卡区分开。这是版式层面的活人感。

## 第二批能学的（写进 meme-xhs 写作指南）

1. 第一句是判断或意图，第二句是带专名和数字的事实，信源一句话带过。
2. 知识密集的素材用编号笔记体：每个编号开头一句判断，编号句连起来就是全文结论。
3. 新概念先放进读者已知的清单里当「第 N+1 个」，用平行句式对比，名字放在解释后面。
4. 一篇只用一组例子，从头用到尾。
5. 每篇一次「换一群读者再讲一遍」：程序员版给一段伪代码，非技术版给一个工作里的场景。
6. 读者会问的反驳替他问出来，让步句带事实，再接住。
7. 回指自己已经发过的稿子。
8. 证据截图画红框，图前面先说结论。
9. 单句段只用三种：带态度的判断、说话人的动作、给上文起名。
10. 标题备选三条里，素材有两边时至少一条写成对比句（「X 的路子，和 Y 完全不一样。」）。
11. 结尾先降温再一句温和判断，或者停在功能说明上。
12. 字体：宋体试过一次（10-03 Uber 稿），用户定回黑体，不再试。

## 第二批不能学的

- 「Jev 背后的公司 TypeSafe 提出来的一套新的训练方法」：他上手跑了项目，这句站得住；我们没跑过就不写「我上手做了很多 Case」。
- 「大家各美其美」「真的很厉害」：抒情句，账号语气是毒舌，不用。
- 他的 Kimi 稿读起来有合作稿的可能（官宣截图两张、「这就是生态」），我们写公司时立场只从自己工作里的体感出发，不替任何一家公司站台。

# 第三批（10-05 补）：Personal Agent 稿，对照我们的路线图稿 v2

用户 10-05 看了路线图稿 v2（已经按第二批规则改过口吻）说「文风还是很怪」，发来这篇让对照。这一轮的结论：**差距不在句式，在判断的对象、骨架的来源和场景的有无。** 第二批的规则治的是表层，这三样没动，怎么换口吻都像解读。

## 七条差距（每条都拿两边原句对照）

**25. 判断对着世界下，不对着文章下。** 小盖：「我相信未来海底捞肯定会提供一个订餐的 Agent」「App、SaaS、平台应该都会变成 Agent 背后的供应商」「谁掌握了用户的意图，谁就拿到了最上游的入口」。我们：「整篇我就认这一条」「这条我不同意」「文末那条雇佣标准我觉得比路线狠」。他押的是未来，我们打的是分。stance 的对象是文本，读者就把你当读书笔记。

**26. 每个抽象点下面都有一个带时间地点的生活场景，而且是「假设我」。** 「假设我今天上午十点要去拜访一个客户，九点半它检查路况」「我刚刚还在折腾 10 月 6 日的海底捞订餐，家人过生日」「我问他周三有没有时间，他说没空，给我两个时间，其中一个我在出差」「我要去上海出差，分别打开机票、酒店、打车」。这些不是要核实的经历，是日常推演，谁都不会去查。我们把「只写真事」做成了「不写场景」，「我」只剩一个 PM 头衔。假设式场景不违反真实性。

**27. 骨架是他自己的五个判断，不是原文的章节。** 他的五个小标题：会不会主动行动、Token 消耗再跃迁、隐私靠技术解决、Agent Network 水到渠成、下一代互联网总入口。没有一个是 Noah Shinn 或 Ben Thompson 的目录。我们的 1 到 7 就是 Month 1 到 Month 6。骨架跟着原文走，换什么口吻都是解读。

**28. 有犹豫、重复和零信息的句子。** 「好像，应用的时代应该真的来了。真的来了。」「现在不敢下结论。」「这个思路我觉得是可行的。总之就是……」「是的，它更像是……所以，也不能叫炒作。」这些句子没有信息，但读者一看就是人在想。我们每句都是写完的，连「HR 认不认我不知道」也是设计出来的毛边。

**29. 段落长短差很多，单句段占三分之一，而且带「真正」「本质上」。** 「AI 行业的风向变化实在太快了。」「Personal Agent 开始有眼力见了。」「AI 的工作时间，开始和人的在线时间脱钩。」「真正重要的是，用户的意图。」「所有的创新本质都是 Mix。」全是我们黑名单会 ✗ 的东西。他用了没人说 AI 味，因为前一段刚讲完海底捞或者打车，这句是场景讲完后的一声感叹。10-02 被骂的单句段，前一段是另一句抽象话。病因不是「单句段」，是「抽象接抽象」。现在 meme_check 把节奏拉成一样长的段落，反而更像机器。

**30. 没有领取物、没有自测、没有 headline。** 他的结尾停在「谁掌握了用户的意图，谁就拿到了最上游的入口」。我们的「四个自测问题」和首页那行「2.6 万人收藏的 AI 工程师路线图」是营销号的两个标志。09-30 定的「产出占后半篇三分之一」直接带来了课程感。他这种号的关注来自「这人对行业有看法」。

**31. 名词来自行业当下，不来自原文。** Muse、Meta Secure VM、Confidential VM、OpenClaw、Instinct 三点前打电话、克里斯坦森 JTBD、字节腾讯阿里。我们是 CS50P、LlamaIndex、Chroma，全是那篇文章里的。读者判断「这人在不在行业里」靠的是他顺手提到的东西。

## 他这篇的弱点（不学）

「本质上」「真正重要的是」密度偏高；「当然」出现三次；「这个话题我后面还想单独写一篇」是预告，账号规则不允许；小标题「一、二、三」是知乎体，我们用「1、」就行。
