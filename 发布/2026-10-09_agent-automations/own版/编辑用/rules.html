Anthropic 那个每天发简报的 agent，六条规矩

来自 claude.dev 博客 Building effective agent automations（Lance Martin、CJ Avilla，10-08），参考实现在 claude-quickstarts 仓库的 managed-agents/daily-brief
1每个源记一个书签，不读「过去 24 小时」跑完把每个源最新一条的时间戳写进 bookmarks.json，下次从那接着读。跑晚了不漏，跑早了不重
2读不到不等于没事MCP 挂了、token 过期，任务照跑但看不到那个源。规矩：书签原地不动，简报末尾写一行「PR 这次没读到」
3发之前每条再核一遍读完到发出去之间世界在变。没了就删，变了就改，查不到就删并记进 cuts。拿不准的一律不发
4Slack 回 ok 才算发了先查频道里今天的标题发过没有；回了 ok 和消息 ts 才算；之后才更新账本和书签。不确定就标「maybe posted」，别的不动
5偏好每次跑都重读，agent 只读不能改偏好写进提示词会一直按旧规矩跑。放在一个它改不了的文件里，读不到就停下说一声，不按默认跑
6只读的地方只给只读，每次跑有花费上限GitHub token 只读、网络只到白名单；上限先设正常一次的 3 到 5 倍，撞上限是暂停不是报错，设太低的症状是简报突然不来了
agent 本身只做一件事：判断哪几条你今天会动手，发出去。「12 个 PR 待审」不算一条，大多数日子只有几条，有时候一条没有。
