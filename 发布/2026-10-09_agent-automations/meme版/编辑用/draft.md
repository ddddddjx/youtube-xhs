上个月底把公司企业版的 Codex 额度花完了。我每天跑着十几个定时任务，公司的在 Codex 的 scheduled jobs 里，自己的还有一堆，比如一个 Grok bot 每天定时抓推特上我感兴趣的内容。烧钱的是公司那批：我让它们定时生成 ChatGPT 的 sites，背后每次都是很重的 MCP 查询和计算，token 消耗很快，而且数据一重，sites 的组装经常混乱，数据源和前端展示都会出问题。

所以 Anthropic 昨天发的那篇讲定时 agent 的参考实现，我是对着自己的账单读的。

两个工程师 Lance Martin 和 CJ Avilla 写的，例子是一个 agent 工作日早上 7 点 32 分自己醒来，读几个 Slack 频道和 GitHub 的 PR，发一条简报到 Slack。

配置一共 8 个文件，一条命令建好，跑在 Anthropic 的机器上。

它和我那十几个任务最大的不同，是它什么都不生成。不出页面，不算数，不组装，只判断哪几条你今天会动手，然后发出去。文章原话：「12 个 PR 待审」不算一条，大多数日子只有几条，有时候一条没有。读完我把它的六条规矩按自己的任务过了一遍，三条回去就加，一条我反着来。

1、紧急程度不高的内容，它说今天没事，我会信

Grok bot 哪天跟我说没抓到新东西，我不会去推特验证。文章讲的那个坑正好在这：MCP 挂了、token 过期了，任务照样跑，只是看不到那个源，然后它汇报「今天没事」。你以为是安静的一天，其实是它瞎了一只眼。

它的解法是两句规矩写进 agent 的说明文件：某个源读不到，这个源的书签原地不动，简报末尾加一行「PR 这次没读到」。书签是另一条，每个源记一个「上次读到哪」的时间戳存在文件里，下次从那接着读，跑晚了不漏，跑早了不重。

信它说没事的前提，是它得先学会说「我没读到」。我那些 sites 数据源和前端对不上，现在回头看，多半就是某一步读空了，后面照常组装。

2、我会给它 full access

文章里 GitHub 的 token 是只读的，偏好文件 agent 只读，沙箱只能连白名单里的域名。理由是它读的 Slack 消息和 PR 都是别人写的，里面要是埋了指令，只读的 agent 最多把简报写歪，改不了你的仓库和规矩。

对它那个只发简报的 agent，只读当然够。我那些任务要查数、要算、要出页面，只读等于没用，我要的是它把活干完，不是给我发一份清单。代价就是上个月那张账单。

不过文章同一节里还有一条，我回去就加：每次跑的花费设上限，先设正常一次的 3 到 5 倍，跑几次看真实数字再收紧。撞上限的那次是暂停，不报错，所以上限设太低的症状是「简报突然不来了」。full access 加一个上限，比只读加无限额度像一个 PM 会做的选择。这条我回去就给十几个任务都加上。

3、最担心的不是它干坏事，是它不能完美理解我的要求

文章里最像「要求」的地方是 agent 说明文件的第 4 步和第 5 步。第 4 步把「什么算一条」写成一个能判断的句子：读者今天会为它动手，或者它改变读者正要做的一个决定。

第 5 步是发之前每条再去源头查一次，没了就删，变了就改，查不到就删掉记进当次的记录。它还有一句，一条过期的「还在等你」比漏掉十条更伤信任，所以状态不许含糊，要么断定要么删。

我那些 sites 组装混乱，说到底是我没把「组装对了」写成它能自己查的条件。我给的要求是「生成一个 site」，它理解成什么样就是什么样，数据源错了它也不知道自己错了。文章的 agent 还有一个账本文件，记每条报过的东西、来源、一个不变的 ID 和最后状态，所以不重复报，也不漏报。我的任务没有这个账本，每次都是从零开始的一次性发挥。

换成不写代码的人，这件事是：你让 AI 每天早上盯着工作群，挑出「今天要你拍板的」，第一步是先写清楚什么叫要拍板。写不清楚，它每天给你的就是一份看起来很努力的清单。

4、两年后 PM 的一天里，这种自己跑的 agent 已经能稳定闭环很多中型的任务

文章这个 agent 今天干成的是一个小任务：读两个源，发一条。为了不出错，用了 8 个文件、6 条规矩、一个账本和一个书签文件。中型任务是我那种，查数、算、出页面、发给人看，每一步都能错。

从小到中，差的是这六条规矩每条都要为中型任务重写一遍：书签记什么，读不到怎么说，发之前核哪几样，什么算发成功，花费上限设多少。我上个月是先烧光额度，再回来补这些。
