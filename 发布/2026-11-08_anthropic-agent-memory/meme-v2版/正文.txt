Anthropic 两天前发了一篇讲 agent 记忆的文章，里面一场宝可梦实验很说明问题：一个 Claude 写了 413 个记忆文件，只拿到 1 个徽章；另一个只写了 10 个文件，拿到 4 个。记得多的那个，越往后越要花时间翻自己的笔记，有 17 步一步游戏都没走。我给 Claude Code 写的规则文件也是这样，越改越长，产出反而越来越不稳定。

文章里四件事对我有用：
1. 记忆有时候是一种预测，写下一条规则等于在赌它还会再出现。屏幕上能直接读到的不记，只记自己琢磨出来、验证过的规则
2. 给模型一条死规则「只记录失败」，Opus 5 从记忆里得到的提升几乎全丢了。Anthropic 的结论是：告诉它记忆是干什么用的，不告诉它怎么用
3. Claude Code 的文档也写着，指令文件越长模型遵守得越差，所以自动记忆每次只加载前 200 行
4. 写错的一条笔记会被一直相信，Claude 在同一道悬崖上掉了三次。修法叫 dreaming：空闲时回头把笔记和日志对一遍，改错、合并

我接下来打算这么做，可以照抄：
· 规则文件压到一页，只写目标和这份记忆是为了什么
· 每条规则旁边标上它是哪一次翻车加进来的
· 每两周对一遍日志，两周没用上的那条删掉

原文：Anthropic《The Components of Agent Memory》，2026-11-06。
