越来越觉得，AI 工程师这个岗位的门槛，被「工程师」三个字抬高了。3 月份 X 上有篇一万多词的长文，讲怎么用 6 个月从零变成 AI 工程师，7900 多个赞，2.6 万人收藏，两个人写了 40 多个小时。

我是 PM，用 Claude 和 Codex 干活两年，对着这张表从头看到尾，前四个月列的东西，大半是我在干活里被迫碰过的，没有一样是坐下来学的。很多人第一反应会觉得这是给程序员的，其实它更像一张 AI 时代打工人的通用技能表。

1、它对 AI 工程师的定义，先把一半人劝退，又把另一半人拉进来。不是从零训练大模型，是在现成模型上做产品。

具体是：接 API、设计提示词和上下文、做聊天、搜索或自动化、接工具和数据库、处理结构化输出、管可靠性和成本、把功能部署出去。

照这个定义，训练模型的研究员不算 AI 工程师，一个把 Claude 接进公司流程的运营算。这是全文最值得记的一句，后面六个月全是从它长出来的。

2、第 1 个月是 Python、Git、终端、HTTP、SQL、FastAPI，目标只有一个：不用再查基础语法。资源全是免费的官方东西，哈佛的 CS50P、MIT 的 Missing Semester、FastAPI 官方教程。

练习是写一个记账的命令行小工具，存 JSON 文件，再写一个调天气 API 的脚本，处理 404 和超时。两个都推上 GitHub。这一个月我没走过，Claude Code 替我写了，我自己只负责看懂。

3、第 2 个月是整张表里我最在意的一行，不写代码的人也该看。提示词、结构化输出、tool calling、流式、多轮状态、token 成本、失败处理、提示注入，八样东西。

换成不写代码的人，这八样是：给 AI 派活时说清要什么格式，给它工具而不是让它猜，记得它没有记忆、每次都要把前面的话重发一遍，算一下这次要花多少钱，它出错了程序别跟着崩，还有别把网上抓来的东西直接当指令喂给它。我上一篇 harness 稿里说的工具和权限，就是这一行。

4、第 3 个月是 RAG，让模型照着你的文档回答，不是照着它的训练数据。切块多大、用哪个向量库、怎么过滤、怎么重排，文里把检索失败分成四种：问法和文档说法对不上、答案被切块切断了、找错了文档、取的条数太少。

这一个月我没碰过，公司里有人做，我只是用。所以这一行我没法替你判断难不难，只能说它给的起点很具体：先用 Chroma 在本地跑，500 字一块，重叠 50。

5、第 4 个月是 agent，这一行我只认一条：先不用框架，用 API 直接写一个 while 循环的 agent，三个工具，一个目标。写过这个循环再去看 LangGraph，才知道框架替你包掉了什么。

给写代码的人，这个循环大概就是：

while True：问模型下一步做什么；模型要调工具就调，把结果塞回对话；模型说做完了就停；超过 10 轮也停。

表里还专门列了什么时候不该用 agent：一次提示能解决的就单次调用，步骤固定的就写工作流，只有步骤和分支真的动态才上 agent。这条我觉得比 agent 本身重要。

6、第 5 个月才是分水岭。Docker、队列、鉴权、日志、prompt 版本管理、成本监控、缓存。前四个月的东西 PM 都能碰到，这一行碰不到，也没必要碰。工程师和「会用 AI 的人」的分界线不在 agent，在这里。

有人可能会说，那前四个月自学了也当不了工程师。确实，当不了。真正能拿到的是另一样东西：你给 AI 派活的时候，知道它底下在干什么，知道哪一步会坏。

7、文末那条雇佣标准我觉得比路线本身狠：六个月结束，手里要有几个能点开的产品，不是学完理论。他自己简介写着 20 岁、CEO、天使投资人，公司名在工商和 YC 名录里都对不上，这些是自述。路线图里的链接倒全是官方文档，一条条点得开。所以把它当带链接的目录用，别当招聘背书。

还有两处要打折：长文在 X 上抓取时从第 4 个月后半截断了，第 5、6 个月的清单是拿他 3 月 13 日的大纲帖和一份日文译本补齐的，不是逐字原文；第 1 个月有一条链接贴错了，19 小时的 API 课和终端命令课指向同一个视频，点之前看标题。

四个问题，自测你在表里第几个月：

1. 给 AI 派活时，会不会先说清楚要什么格式、能用哪些工具？不会，你在第 2 个月之前。

2. 知不知道它这次回答花了多少钱、为什么这次比上次慢？不知道，第 2 个月没过。

3. 让它照着你的文件回答，答错时你能不能分清是没找到文件还是找到了瞎编？分不清，第 3 个月。

4. 有没有写过或者看懂过一个最简单的 agent 循环？有，第 4 个月，大多数 PM 到这里就够了。
