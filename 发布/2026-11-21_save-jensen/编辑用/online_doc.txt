 01运行环境
 小工具是运行在受限沙箱环境里的纯 Web 应用（HTML / CSS / JS），请把它当作一个"能力受限的浏览器页面"来开发。
 📋
 创作入口：使用小工具上传页的改写口令。
 通过上传页手动上传时，无论从零创作还是改写现有 H5，都应在“第一步：调整为符合小红书规范的代码格式”中
 完整复制当前口令并发送给工作区内的 AI 助手。AI 助手须按口令下载对应版本 Skill、
 解压到指定目录、读取 SKILL.md，再对当前产物进行校验、修复和打包；完成后将生成的 zip
 用于上传页第二步。本能力清单用于解释容器边界，不能代替上传页口令，也不要沿用手工保存的旧口令。
 如需由第三方 Agent 管理小工具，请参照下方第三方 AI 工具开发指南。
 技术栈
 标准 Web 技术栈
 使用容器允许的 HTML / CSS / JS 与 Web API 开发；Android 最终产物须同时满足 ES2017 与 Chrome / WebView 61 兼容要求。
 兼容性
 Android 10+ / iOS 18.4+
 Android 产物仍须兼容 Chrome / WebView 61；系统门槛、内核门槛与客户端接口版本分别判断。
 平台能力
 JS API（window.xhs）
 容器自动注入 JS API SDK，可调用 AI 文本生成、发布笔记、关注作者、保存相册、
 云存储、排行榜、窗口信息、定位、振动和陀螺仪等能力；各能力须满足对应客户端版本、开放范围与授权条件，
 详见 §3。无需自行引入脚本。
 沙箱
 安全沙箱
 容器对部分敏感 Web 能力做了限制（详见下文），并对文件选择、页面跳转等做了统一管控。
 隔离
 独立隔离
 每个小工具拥有独立的存储与运行环境，小工具之间互相隔离、无法访问彼此数据，也无法互相通信。
 网络边界
 页面不能主动联网
 页面、脚本、图片、字体等资源必须完整放入上传包，网页不能直接请求外部服务。
 平台管理的静态资源分发见 §2.7，可用平台能力见 §3。
 1.1 第三方 AI 工具开发指南
 你可以将自己小红书账号的小工具管理权限开放给第三方 Agent，
 在自己的 Agent 中完成开发、测试、真机预览、上传和查询审核状态的全流程。
 进入小红书创作服务平台，
 登录自己的小红书账号，找到 Builder Hub → 小工具页面。
 点击页面上的“用agent创作”。
 勾选弹窗中的“让agent帮我管理小工具”，复制开发口令并发送给自己的 Agent，
 按照 Agent 的提示完成后续操作即可。
 ⚠️
 注意事项：若小工具需要使用正在内测的 AI 接口能力，尚无法通过第三方 Agent 上传。

 2.2 JS / CSS 兼容基线
 系统支持 Android 10 及以上、iOS 18.4 及以上；
 Android 产物的最低兼容内核仍为 Chrome / WebView 61。
 系统门槛与内核门槛同时保留；不能把 61 当作 Android 10 的出厂内核，也不能由系统或内核版本保证 WebGL2 或具体 API 可用。
 JavaScript：最终交付代码须编译到 ES2017 / Chrome 61；更高版本语法由构建工具转译。
 CSS：最终样式须兼容 Chrome 61；更高版本 CSS 只能作为增强，并保留基础样式。
 能力检测：使用 Chrome 61 基线外的高级 Web API 或 CSS 能力前，必须先检测是否支持；
 支持时启用增强，不支持时走降级路径。
 开发方式：请复制小工具上传页提供的完整改写口令，让 AI 助手加载对应版本 Skill，
 并严格按照 SKILL.md 完成开发、兼容处理、校验和打包。具体开发规则以 Skill 为准。

 2.7 静态资源优化策略
 按加载需求选择参与优化的静态资源，将它们作为独立文件放进 assets/ 目录，使用本地路径引用并完整打包上传，
 即可在平台启用该策略的范围内享受主包体积优化，减少打开小工具时需要随主包下载的内容。
 不要求把所有资源都放进 assets/：应综合首屏依赖、资源重要性、体积与实际加载表现，兼顾主包大小和首屏体验。
 开发者按正常流程上传发布即可，无需额外接入。
 💡
 最低支持客户端 9.53.3。适用范围以平台发布通知为准。
 该策略仅对新发布生效，存量作品需重新发布后才能参与优化。
 资源文件类型仍须符合 §2.6，页面仍不能直接访问外部服务或 CDN。
 按这四步准备上传包
 先判断哪些资源适合参与优化，再决定存放位置。
 首屏强依赖、非常重要且体积小的资源，可以放在 assets/ 之外随主包下发，
 不参与这项优化，减少首屏等待资源取回的影响。
 体积较大、非首屏或可延后加载的图片、字体等资源，可优先考虑放进包根目录的 assets/，并按需分子目录。
 对首屏必需但体积较大的资源，也应结合实际加载表现权衡，不能仅凭体积或文件类型决定位置。
 入口 HTML、入口 JS / CSS 仍放在该目录之外。
 参与优化的资源使用独立文件，不做 base64 内联。
 不把这些待优化的静态资源嵌进 HTML、CSS 或 JS；内联资源不参与这项优化。
 选择随主包下发的资源可继续使用包内文件路径，无需为了不参与优化而改成内联。
 运行时选图预览、Canvas 导出等场景仍可使用 §2.6 允许的 data: / blob:。
 按本地路径引用，不替换成网络地址。
 例如随主包下发的资源使用 ./critical/logo.svg，参与优化的资源使用
 ./assets/detail.webp 或 /assets/detail.webp；
 CSS 中的相对路径按样式表所在位置填写。
 动态拼接路径（如 image.src = "/assets/" + i + ".png"）也可以，
 但必须确保对应文件实际进入最终上传包。
 完整打包，再按正常流程上传发布。
 上传 zip 中必须包含全部资源，不能自行删掉 assets/。
 上传包示例：假设 logo.svg 是首屏强依赖、重要且体积小的标识，选择随主包下发；
 详情页大图 detail.webp 和非首屏装饰字体 decoration.woff2 选择参与优化。
 critical/ 只是示例中的自定义目录名，也可使用其他位于 assets/ 之外的包内路径。

 2.8 Worker
 最低支持客户端 9.53。仅支持 Dedicated Worker（new Worker()），
 不支持 SharedWorker 和 Service Worker。与标准 Web Worker 的差异如下。
 项目小工具容器约束
 | 脚本入口
 | 仅支持上传包内的 classic .js 脚本。module Worker、外部 URL、blob: / data: 和运行时生成的临时脚本不可用。
 | 实例配额
 | 每个页面同时最多一个 Worker，超出时抛出 QuotaExceededError。调用 terminate() 或平台回收后释放名额。error 和 self.close() 后仍需由页面调用 terminate() 释放。
 | CSP 策略
 | Worker 的 CSP 策略与容器一致，网络请求、脚本加载及动态代码执行受容器限制，见本文“资源加载规则”和“禁用行为”。依赖需预先打包进入口脚本，禁止追加脚本或创建子 Worker。
 | 后台回收
 | 页面连续隐藏 30 秒后回收 Worker，提前返回会取消计时，期间新建实例沿用本轮期限。到期仍隐藏时创建会抛出 SecurityError。返回页面后需重新创建实例、恢复任务数据。
 | worker.onTerminate(callback)
 | 新增终止通知，名额释放后异步回调。参数 "主动" 表示页面调用了 terminate()，"system" 表示平台回收。同一回调对同一实例只通知一次。
 | worker.offTerminate(callback)
 | 注销指定终止回调，省略参数时清理本实例全部终止监听。
 回收通知可能延后执行，页面或进程销毁时不保证收到通知。
 03平台 JS API
 除标准 Web 能力外，容器会自动注入 JS API SDK，小工具可通过
 window.xhs.miniTool.* 调用 App 原生能力：发布笔记、保存图片到相册、
 本地缓存、文件读写、发布评论、关注作者、分享、赞赏、赞赏挽留设置、云存储、排行榜、窗口信息、定位、振动和陀螺仪；
 通过 window.xhs.AI 调用平台对话模型。
 无需在包内引入任何 SDK 脚本。

 未注明最低版本的 API 不得自行推定“所有版本支持”。存储失败不得触发浏览器存储回退，具体规则见
 §3.7。

 3.6 客户端版本判断
 💡
 buildVersion 的末 3 位是编译 / 打包序号，判断客户端版本时必须忽略。
 例如 9462004 表示客户端 9.46.2、编译序号 004。
 window.xhs、launchOptions、miniToolEnv 和
 buildVersion 都可能缺失，同步读取时必须逐级判空。同步值不存在时，
 在确认 window.xhs.miniTool.getLaunchOptions 是函数后，再异步获取客户端值。
 两种方式都无法取得有效版本号时，状态为版本未知：不得按低版本进入浏览器存储兼容路径。
 客户端版本仅用于对应原生接口的版本判断，不能代替操作系统、实际 WebView 内核或权限检查。
 function readBuildVersion(launchOptions) {
 const miniToolEnv = launchOptions && launchOptions.miniToolEnv;
 const value = miniToolEnv && miniToolEnv.buildVersion;
 if (typeof value !== "number" && typeof value !== "string") return null;
 if (!/^[1-9]\d{6,}$/.test(String(value))) return null;
 const version = Number(value);
 return Number.isSafeInteger(version) ? version : null;
}
async function getBuildVersion() {
 const xhs = window.xhs;
 const syncBuildVersion = readBuildVersion(xhs && xhs.launchOptions);
 if (syncBuildVersion !== null) return syncBuildVersion;
 const miniTool = xhs && xhs.miniTool;
 if (!miniTool || typeof miniTool.getLaunchOptions !== "function") return null;
 try {
 const launchOptions = await miniTool.getLaunchOptions();
 return readBuildVersion(launchOptions);
 } catch (error) {
 console.warn("getLaunchOptions failed; client version remains unknown");
 return null;
 }
}
function getClientVersion(buildVersion) {
 // 例如 9462004 / 1000 取整后为 9462，即客户端 9.46.2
 return Number.isSafeInteger(buildVersion) && buildVersion > 0
 ? Math.floor(buildVersion / 1000) : null;
}
function isClientVersionAtLeast(buildVersion, minimumClientVersion) {
 const clientVersion = getClientVersion(buildVersion);
 return clientVersion !== null && clientVersion >= minimumClientVersion;
}
async function getMiniToolForClient(minimumClientVersion, methodNames) {
 const buildVersion = await getBuildVersion();
 if (!isClientVersionAtLeast(buildVersion, minimumClientVersion)) {
 console.warn("Capability unavailable: client version unknown or too old");
 return null;
 }
 const miniTool = window.xhs && window.xhs.miniTool;
 if (!miniTool || !methodNames.every((name) => typeof miniTool[name] === "function")) {
 console.warn("Capability unavailable: SDK or method missing");
 return null;
 }
 return miniTool;
}
 3.7 Storage — 小工具本地缓存
 💡
 最低客户端 9.46.0；正常业务统一使用容器 Storage。
 明确低于该版本时可提示升级；确需兼容时须单独实现必要兼容路径，并处理浏览器存储不可用或被清理。
 版本未知、SDK / 方法缺失、权限拒绝、超额和调用失败均不得回退到
 localStorage、sessionStorage、IndexedDB、Cookie 或 Cache API。
 历史数据迁移只读取旧数据，不继续向旧存储双写；完成迁移后业务只读写容器存储。
 const STORAGE_MIN_CLIENT_VERSION = 9460; // 客户端 9.46.0
async function setLocalData(key, data) {
 let serializedData;
 try {
 serializedData = JSON.stringify(data);
 } catch (error) {
 console.warn("Storage data serialization failed");
 return false;
 }
 if (typeof serializedData !== "string") return false;
 const buildVersion = await getBuildVersion();
 const miniTool = window.xhs && window.xhs.miniTool;
 if (buildVersion === null) {
 console.warn("Storage unavailable: client version unknown");
 return false;
 }
 if (!isClientVersionAtLeast(buildVersion, STORAGE_MIN_CLIENT_VERSION)) {
 console.warn("Storage requires client 9.46.0 or later");
 return false;
 }
 if (!miniTool || typeof miniTool.setStorage !== "function") {
 console.warn("Storage unavailable: SDK or method missing");
 return false;
 }
 try {
 const result = await miniTool.setStorage({ key, data: serializedData });
 const saved = !!result && result.errMsg === "setStorage:ok";
 if (!saved) console.warn("Storage did not confirm a successful write");
 return saved;
 } catch (error) {
 console.warn("Storage write failed; save was not confirmed");
 return false;
 }
}
 调用方必须处理 setLocalData 返回 false 的情况，
 保留当前输入并提示未保存；不能假设数据已成功持久化。该示例只包含正常写入路径；
 必要兼容路径必须先取得有效版本并确认 clientVersion !== null && clientVersion < 9460
 （clientVersion = getClientVersion(buildVersion)），
 不得从通用 catch、版本未知或方法缺失分支进入。
 已有工具的数据衔接
 先调查历史版本的存储位置、key、数据结构、账号归属和有效期；未读到数据不能直接认定用户从未保存。
 在支持容器 Storage 的客户端中，以容器数据为准；仅对尚未迁移的历史记录读取旧存储。两处都有数据时须先确定冲突规则，不能用旧值覆盖用户的新修改。
 按业务数据版本转换并校验旧数据，逐项写入容器 Storage，再读回核对；全部待迁移记录确认成功后才能记录迁移完成。
 迁移须可重试且重复执行不覆盖新数据。读取、解析、写入或校验失败时保留旧数据，不标记完成，也不删除唯一副本。
 迁移完成后停止业务对旧存储的读写；只按已确认的迁移范围清理本工具旧 key，不调用全量清理破坏无关数据。历史数据已被清理时应如实提示，不能承诺可恢复。

 if (err.errCode === 20002) return; // 用户关闭确认框或拒绝授权。

 followNotice = "今日关注引导次数已达上限";
 return;
 }
 if (err.errCode === 10003) return; // 关注确认流程仍在进行。
 console.log(err.errMsg || err.message);
 } finally {
 followPending = false;
 renderFollowStatus(currentFollowStatus);
 if (followNotice && followStatusText) {
 followStatusText.textContent = followNotice;
 }
 }
}
if (followButton) {
 followButton.addEventListener("click", onFollowClick);
}
refreshFollowStatus();
 两个方法均只针对当前小工具作者；不能通过传入用户 ID 改为关注或查询其他用户。
 查询关注状态可用于刷新自绘关注按钮；follow_status: -1
 表示暂时无法确认状态，可由后续查询重试。
 未登录时查询返回 follow_status: 0。已登录用户在小红书 App
 的其他入口取关后，进程内缓存可能使查询暂时返回旧状态；App 重启后再查会读取更新后的关注状态。
 3.16 云存储（内测）
 💡
 云存储为内测能力，尚未正式开放。内测阶段能力与限制可能随版本调整，
 请勿将其作为核心功能的唯一依赖。云存储 API 需要客户端 9.51+，
 可复用 §3.6 的版本判断方式，以 9510
 作为最低客户端版本判断值；调用前先做方法存在性探测，未授权（errCode 1006）时隐藏入口并降级。
 云存储提供「用户 × 小工具」隔离的个人数据：同账号换设备后数据可恢复，
 创作者不可见用户存储内容。collection 为业务分类（相当于数据表名，如
 todos）；content 为完整业务 JSON 对象，不是字符串。
 逐项写入结果的 status 为三态：SUCCESS 已完成 /
 FAILED 确认失败 / UNKNOWN 结果不确定。
 API
 参数
 结果 / 说明
 | addCloudStorage
 | collection: string、items: { content }[]（非空数组；每项 content 必须为对象，传字符串会在本地报错）
 | 
 批量新增，返回 { data: [{ id, status }] }；id 为服务端生成的
 24 位十六进制。逐项结果按位置与输入一一对应，不要用返回 id 做对应；
 UNKNOWN 且后端未返回 id 时该项 id 为空串
 | updateCloudStorage
 | collection: string、items: { id, content }[]（非空数组，同批不允许重复 id）
 | 
 批量整行覆盖（非字段合并）：未提交字段不保留，要保留的字段必须一起提交。
 返回逐项 { id, status }（后端未返回 id 时回退输入 id）
 | queryCloudStorage
 | collection?、ids?、limit?、cursor?
 | 
 统一查询，返回 { items: [{ id, collection, content }], nextCursor?, hasMore? }。
 传 ids（非空、不重复）为点查，此时 collection 必填，
 只返回命中记录、不返回分页字段；只传 collection 为分类分页；
 都不传为跨全部分类分页
 | removeCloudStorage
 | collection: string、ids: string[]（非空、不重复）
 | 
 按 id 批量硬删；重复 id 在 SDK 本地直接拒绝（errCode 10001，请求未发出）；
 幂等（目标不存在也成功）。返回逐项 { id, status }
 const miniTool = window.xhs && window.xhs.miniTool;
const res = await miniTool.addCloudStorage({
 collection: "todos",
 items: [{ content: { text: "买菜", done: false } }],
});
// res.data[0]: { id, status }
const page = await miniTool.queryCloudStorage({ collection: "todos" });
// page: { items: [{ id, collection, content }], nextCursor?, hasMore? }，limit 默认 20
await miniTool.updateCloudStorage({
 collection: "todos",
 items: [{ id, content: { ...old.content, done: true } }], // 整行覆盖，要保留的字段必须一起提交
});
await miniTool.removeCloudStorage({ collection: "todos", ids: [id] });
 批量写非事务：顶层成功（含部分成功）不等于每条成功，必须逐项判 status；FAILED 可重放，UNKNOWN 走 queryCloudStorage 对账。
 updateCloudStorage 无版本校验：多端并发编辑同一记录时，以后生效的写入为准。
 分页以 nextCursor 逐页翻取，末页不返回该字段；limit 须为正整数（默认 20），翻页时查询参数保持一致。翻页不保证跨页快照一致，期间的新增和删除可能影响后续页；游标版本变更后旧游标失效，需从首页重查。
 读取失败整次 reject，items: [] 才代表「确实没有」；不得把读失败当无数据渲染。
 删除不可恢复；删除后如有在途延迟写请求，可能重建同 id 记录。
 配额上限：单批最多 100 条（items / ids，超限返回 1002）；单条 content 经 JSON 序列化（UTF-8）后不超过 64KB（65536 字节），超限返回 1003。存档类数据只存必要字段、剔除静态配置；超大存档自行分条拆分（主记录 + 分段记录）。
 接口限频：云存储 / 排行榜全部接口按「小工具 × 接口」维度限频，默认每个小工具每个接口 150 QPS（一次调用消耗一次额度，批量条数不额外拆分），超限返回 2009 且发生在鉴权之前。请勿在游戏循环 / 高频定时器里直接调用：写入先在本地节流合并（如分钟级落一次云），榜单结果做本地缓存（30s ~ 60s）后再展示。
 3.17 排行榜（内测）
 💡
 排行榜为内测能力，尚未正式开放。内测阶段能力与限制可能随版本调整，
 请勿将其作为核心功能的唯一依赖。排行榜 API 需要客户端 9.51+，
 以 9510 作为最低客户端版本判断值，判断方式见 §3.6；
 未授权（errCode 1005）时隐藏排行榜入口并降级。
 排行榜提供公开成绩榜单与本人排名。board 为榜位整数 1–5（默认 1）；
 period 为周期枚举 "all" | "month" | "week" | "day"（默认
 "all"），非法值会在本地直接报错（errCode 10001，请求未发出）。
 昵称由平台填充并仅在返回值中出现，不得自行采集或存储用户小红书资料。
 API
 参数
 结果 / 说明
 | submitScore
 | board?、score: number
 | 
 提交成绩（绝对分数，原值不缩放、不取整，须在 -1,000,000 ~ 1,000,000
 区间内，超出返回 1004）。返回 { score }：总榜历史最高分（已合并本次提交）
 | getRankList
 | board?、period?
 | 
 返回 { data: [{ rank, score, nickname }] }：前 100 名，
 按分数降序；limit 不开放，固定返回 100 条
 | getMyRank
 | board?、period?
 | 返回 { status, rank, score }；先判 status 再消费 rank / score
 const miniTool = window.xhs && window.xhs.miniTool;
const mine = await miniTool.submitScore({ board: 1, score: 96.8 });
// mine: { score } —— 总榜历史最高分
const list = await miniTool.getRankList({ board: 1, period: "day" });
// list.data: [{ rank, score, nickname }]
const my = await miniTool.getMyRank({ board: 1, period: "day" });
// my: { status, rank, score }
 ⚠️
 上传授权：使用 submitScore 的小工具，上传至创服平台时必须勾选「用户头像昵称授权」，
 榜单展示的用户昵称依赖该授权；未勾选时排行榜调用会按未授权失败处理（errCode 1005，见下方错误码表），
 应隐藏排行榜入口并降级。
 getMyRank 的 status 取值（SDK 原样透传后端状态值，
 均为查询成功的业务状态，不是错误）：
 status
 含义
 rank / score
 | EXACT | 前 500 名内，精确名次 | rank 为 1–500；score 为本人最好成绩
 | OVER_LIMIT | 有成绩但在 500 名外 | rank 与 score 均为 null，建议展示「500+」
 | NO_SCORE | 已参与但本期无成绩 | 均为 null
 | NOT_PARTICIPATING | 未参与 | 均为 null
 各周期只保留最好成绩，更低分提交也算成功（返回历史最高分）；同分先写入者靠前，名次唯一不并列。
 score 须为有限数值且在 -1,000,000 ~ 1,000,000 区间内，超出返回 1004。数值量级大的游戏（挂机 / 养成 / 经营类）先换算单位（如以「万」计）再提交，同一榜单内保持单位一致即可比较。
 接口限频同云存储：默认每个小工具每个接口 150 QPS，超限返回 2009；勿在游戏循环 / 高频定时器里密集调用，榜单结果做本地缓存（30s ~ 60s）后再展示。
 一次提交在服务端事务内拆总 / 月 / 周 / 日四榜；周期按北京时间 0 点重置（每周一、每月 1 日），新一期不沿用上期成绩，不提供历史榜单查询。
 榜单缓存未就绪返回 2002，不能当空榜或榜外渲染，应显示加载态并做有限次退避（如 500ms / 1s / 2s / 4s）；data: [] 才是真实空榜（确实没人上榜）。
 nickname 用户资料暂缺时为 null，渲染自行兜底。
 云存储与排行榜错误码
 失败对象为 { errMsg, errCode? }，判码用 errCode 整数：
 后端业务失败为后端整数码原值透传；10001 为本地参数错；10003 为容器白名单拒绝；
 网关层失败不带 errCode。
 errCode
 含义
 处理
 | 1001 / 10001 | 参数不合法（后端 / 本地） | 修正参数，重试无意义
 | 1002 | 批量条数超限 | 拆批后重试
 | 1003 | 单条内容过大（content 超过 64KB） | 精简 content
 | 1004 | 分数超出 ±1,000,000 / 非有限值 | 修计分逻辑 / 换算单位
 | 1005 / 1006 | 排行榜 / 云存储未授权 | 隐藏入口，降级
 | 2001 | 存储读写失败 | 常规错误处理，勿伪装成「无数据」
 | 2002 | 榜单未就绪 | 有限次退避，勿当空榜
 | 2003 | 批量部分成功 | 走成功路径，逐项判 status
 | 2004 | 写入结果未知 | 标记待确认，query 对账，禁止重发
 | 2005 | 存储记录唯一键冲突 | 核对冲突来源后再决定重试策略
 | 2008 | 授权服务不可用 | 稍后重试一次，仍失败则降级
 | 2009 | 该应用调用此接口过于频繁（按「小工具 × 接口」限频，默认每个小工具每个接口 150 QPS） | 降低调用频率，勿密集轮询
 | 2999 | 内部错误 | 可重试一次并控制频率
 | 10003 | 容器白名单拒绝 | 反馈平台开通

 💡
 需要客户端 9.53.3+（iOS / Android），以 9533
 作为最低客户端版本判断值，判断方式见 §3.6。

 | errMsg

 3.20 setCloseRetentionEnabled — 赞赏挽留开关（内测）
 💡
 需要客户端 9.53.3+（iOS / Android），以 9533
 作为最低客户端版本判断值，判断方式见 §3.6。
 低于该版本时跳过赞赏挽留设置，保证核心功能可用。
 赞赏挽留必须配合 §3.19 赞赏 使用，无法单独使用。
 开启后，用户关闭当前小工具容器时，客户端可拉起赞赏挽留，引导用户赞赏当前小工具。
 接入前需先开通当前小工具的赞赏能力。此接口设置是否允许拉起赞赏挽留，开关默认 false，
 重复设置以最后一次为准；状态仅属于当前容器，不跨容器或跨次打开保留，
 容器关闭后释放，再次打开恢复默认值。
 请求参数
 字段类型必填说明
 | enabled
 | boolean
 | 是
 | true 允许关闭容器时拉起赞赏挽留；false 关闭赞赏挽留。需配合赞赏使用，必须显式传入布尔值，不接受数字或字符串
 成功返回
 字段类型说明
 | errMsg
 | string
 | setCloseRetentionEnabled:ok；无额外业务数据
 成功仅表示开关已更新；关闭容器时实际是否拉起赞赏挽留、后续赞赏流程及容器关闭由客户端处理。
 设置 enabled: true 不会立即拉起赞赏挽留，也不会单独开通赞赏能力。
 错误码
 errCode说明
 | 10001 | 缺少 enabled 或值不是布尔类型
 | 10002 | 当前调用上下文没有可用的小工具容器
 其他客户端错误通过 errCode 与 errMsg 返回，遵循 §3.1 的失败约定。
 调用示例

 return;
 }

 console.log(result.errMsg); // "setCloseRetentionEnabled:ok"
 } catch (error) {
 console.log(error.errCode, error.errMsg);
 }
}
await setCloseRetentionEnabled(true); // 允许用户关闭当前容器时拉起赞赏挽留
await setCloseRetentionEnabled(false); // 关闭当前容器的赞赏挽留

 06常见问题 FAQ
 创作或改写小工具应该从哪里开始？
 从小工具上传页开始。在“第一步：调整为符合小红书规范的代码格式”中完整复制改写口令，
 发送给工作区内的 AI 助手执行。口令会指导 AI 下载当前版本 Skill、读取
 SKILL.md、校验和修复代码并打包；不要只把本页能力清单当作改写提示词。
 <input type="file" accept="video/*"> 为什么只能选图片？
 出于安全考虑，文件选择仅支持图片和视频，无论 accept 如何设置，此限制不可更改。
 页面里的 <script> 不执行 / 报 CSP 错误？
 容器禁止内联脚本与行内事件处理器（onclick="..."）。请把 JS
 放进包内 .js 文件用
 <script src="./app.js"> 引入，事件用
 addEventListener 绑定。详见 §2.6。
 能不能请求我自己的服务端接口 / 加载线上图片？
 网页不能通过 fetch、XMLHttpRequest 等方式请求外部服务，线上资源也不能直接加载。
 页面、脚本、图片、字体和静态数据必须完整放入上传包。
 §2.7 静态资源优化策略由容器透明取回平台管理的资源，页面仍使用同源路径，不能直连 CDN。
 需要服务端实时推送怎么办？
 不支持 WebSocket / SSE / WebRTC 或通过 fetch 轮询自建服务。
 当前平台 AI 仅支持 §3.10 的非流式文本生成。
 第三方库报安全错误 / 无法运行？
 请排查 §4 中的动态执行、WebAssembly 和网络请求限制。使用 Worker 的库还需符合 §2.8 的脚本、配额和运行限制。
 怎么把小工具生成的图片保存到相册 / 发成笔记？
 用容器注入的 JS API：writeTempFile 把 base64 换成
 filePath，再传给 saveImageToPhotosAlbum 或
 postNote。详见 §3。
 小工具能不能直接做 AI 对话、文案生成或灵感助手？
 可以。使用 window.xhs.AI 调用平台对话模型，无需 API key 或自建服务。
 当前是非流式文本生成，内测阶段需先完成 appId 加白；接入与限制见 §3.10。
 window.xhs 是 undefined？
 说明当前环境未注入平台能力（如在普通浏览器中预览）。请按需检查
 window.xhs && window.xhs.miniTool 或
 window.xhs && window.xhs.AI。原生 API 还需独立核对有效客户端最低版本、方法存在、容器开放与权限；
 不可用时停用功能、提示或只在内存保留未保存内容，不伪造成功。
 版本未知、缺 SDK / 方法、拒绝、超额或失败不得回退浏览器存储、私有 bridge 或外部请求；已知低版本必要兼容按 §3.7 单独实现。
 JS API 传网络图片地址为什么失败？
 这些媒体字段不接受网络地址，只接受 data: base64 或
 writeTempFile 返回的本地路径。
 能不能调用文档里没列出的其他原生能力？
 不能。§3.2 列出的即为全部可用 JS API，未列出的能力不受支持。

 从源码到最终 ZIP 的四个检查点
 入口与依赖。 保留静态首屏和关键 CSS。列出入口必需模块、桥接能力、后续场景及其资源。检查依赖和插件是否引入外域请求、动态代码执行、WASM 或不支持的 Worker。

 打包与复现。 清理专用输出目录再构建，补齐 HTML 与静态文件，检查 ZIP 根入口、文件白名单和分片路径。调试映射保留在开发侧，交付包排除 .map。同一包完成浏览器、模拟器与真机验收。

 质量档与降级策略
 从经过验证的低档或中档起步，控制画布像素、纹理、粒子与后处理。连续渲染时用前台稳定窗口观察帧间隔，
 排除启动编译、页面隐藏和按需绘制空闲期。以 30 FPS 为目标时一帧约 33.3 ms，仍需为输入、业务逻辑和渲染共同留出预算。
 多个窗口持续超预算时逐档降低画质，避免按单帧抖动频繁切换。能力检测失败或 Shader 无法绘制时，直接尝试兼容实现。

 按显示尺寸导出纹理，计算解码、GPU 副本、mipmap 和渲染目标。压缩文件字节数与运行时显存分开记录。
