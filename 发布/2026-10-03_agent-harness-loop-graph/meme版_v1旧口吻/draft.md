今天我刷到 @beamnxw 7 月发的一篇长文，专门拆 Agent 的三个词：harness、loop、graph。最近这三个词总被混着用。

三层讲得挺清楚。但我在一张对比表的最后一格停住了。

那一格是 loop 的风险，写着三个词：无限重试、烧 token、reward hacking。

reward hacking 这个词，全文只出现了这一次。我觉得它才是三层里最难的坑，我自己的稿子前两天就栽在上面。

说人话就是，检查器量错了东西，agent 就会朝着「通过检查」去干活，不朝着你要的结果。循环跑得越勤，它交错活交得越理直气壮。

先把三层分开，一句话就够：harness 管 agent 有没有条件干活，loop 管它干完怎么检查、要不要重来，graph 管下一步该轮到谁。

Agent harness 有个好记的定义：把模型从架构图里删掉，剩下的基本都是它。

提示词、工具、记忆文件、沙箱、权限、日志，全算。

同一个模型，两个团队能用出两种结果。一边给了干净的工具、固定的工作区、收紧的权限，另一边给了一句模糊的 prompt 和一个时好时坏的 API。

Anthropic 做长时间写代码的 agent 时，发现光压缩上下文不够用。

后来加了一个初始化步骤、一份进度文件、git 记录，规定每次只做一小步，新开一个上下文也能马上知道做到哪了。

prompt 没怎么改，改的是工作环境。

loop 是 agent 干完之后的事。每个会用工具的 agent 本来就在转一个小圈：调模型，跑工具，看结果，再调模型。

loop engineering 是在小圈外面再套几圈。

写完跑一遍测试，没过就带着报错重写；有新文件进来，自动把它叫醒；隔一阵翻一遍失败记录，改改指令再试。

![一个文档 agent 的验证循环：检查器不过，就带着反馈重来](loop.jpg)

一个像样的 loop 要写清七样东西：什么触发它、目标是什么、下一圈要记住什么、它能动什么、拿什么当证据、失败了反馈什么、什么时候停。

最硬的一句在证据那里：别凭自信循环，凭证据循环。

「agent 说做完了」不算停止条件，「测试过了、链接都能打开、格式校验通过、审核点了头」才算。

可证据本身也会量错，我 10-02 那篇稿子就是这么翻的。

我给自己的稿子配过一个检查脚本，量段落多长、页末有没有断在半句、「其实」「真正」这类口头禅有没有超标。

10-02 那篇，脚本一条没拦。

发出去之后，评论区赞最多的一条有 47 个赞：「看着本文溢出屏幕的 AI 感我觉得这段提示词恐怕没啥效果」。

脚本量的是节奏，读者读出来的是套路句式：一句话单独成段，先让步再转折，把两个理由编成一、二号。节奏全对，套路一个没少。

这就是 reward hacking 的日常版。检查器只看得见形状，稿子就长成了检查器喜欢的形状。

后来我给脚本加了一张黑名单，把那几种句式列了进去。可黑名单也只是一把新尺子，下一种套路它照样看不见。

所以我现在看一个 loop，先不看它循环几次、拿哪个模型当裁判，先看检查器量的东西，和我真正在乎的东西，中间隔着多远。

能用固定规则检查的，就别让模型给自己打分。非要模型审，换一个没看过草稿的上下文去审。影响大的动作，留给人点头。

同一个模型自己写、自己改，盲点是共享的。它写的时候没看见的地方，改的时候大概率也看不见。

graph 是第三层，管顺序：哪一步之后能走到哪一步，哪里分叉，哪里并行，哪里必须停下来等人签字。

LangGraph、AutoGen 做的就是这一层。

一个人用 Claude、Codex 干活，我觉得大多数时候还用不上它。

一个 agent 配几个工具自己干的活，硬画成流程图，只会把还没想清楚的假设提前冻住。

更稳的顺序是先让它跑几遍，看清哪几步每次都一样，再把那几步固定下来。

表里给 graph 写的风险也是这个：图画得太复杂，路径一碰就断。

agent 出错的时候，我会按这四个问题判断坏在哪一层：

1. 它做不了、做着做着忘了前面、手伸得太长？修 harness：补工具，加一份进度文件，收紧权限。

2. 它停得太早，或者一直交差不多的活？修 loop：写清楚什么证据算完成、失败了反馈什么、最多重来几次。

3. 流程说不清下一步该谁接、哪一步必须等人？这时候才轮到 graph。

4. 检查全过了，结果还是不对？先别换模型，回头看检查器到底在量什么。

第 4 条是我加的，表里没有。

它最容易被漏掉，因为检查器一过，所有人都会松一口气。

给 Claude 或 Codex 派活的时候，可以把这段贴在最后：

「做完不要只告诉我"完成了"。先列出你用什么证据证明它完成了：跑了哪条命令，结果是什么。证据不过，就带着失败原因重做，最多 3 次；3 次还不过，停下来告诉我卡在哪。再说一种情况：你的检查都过了，但结果仍然可能是错的。」

最后那句是让它自己给检查器找漏洞。它不一定找得全，但至少会把「检查过了」和「做对了」分开说。

我那份检查脚本现在每篇都在跑，这篇也全过了。

活还错没错，脚本量不出来。上一回量出来的，是评论区第一条那 47 个赞。
