推荐看看 Thariq 这周发的 40 秒视频，他在 Claude Code 团队做工程师，做了一个还没正式上线的 skill，把 plan 做成一个网页。给 Claude Code 的指示写得再明确，做出来还是会偏，碰到过这种事的人，看完会明白偏在哪一步。

推文 4500 多人收藏。他说想拿这个 skill 替换掉默认的 plan mode，现在先放到社区插件市场里收反馈。

视频里的例子是给一个邮件产品加「定时发送」。网页左边是目录，四条需求全是大白话：用户能在写信框里选时间；用户能在一个列表里看和改排好的信；信只在指定时间发，发失败的留着；发失败了要告诉用户。

每条需求下面挂着一个红色的问题。一个用户最多能排几条？发失败要不要自动重试？用户怎么知道失败了？发过和取消的记录留多久？右下角一个按钮，写着还有 3 个要回答。他的做法是，这些问题不答完，plan 就停在这里。

往下是每条需求要动哪些代码。有个叫 CALLS 的框，画成一棵树：写信框组件里加一个「稍后发送」的菜单，它去调一个新接口，后端先查上限、再组装、再写进表。每一行后面跟着文件名和行号，框的右上角写着加 6 行、删 0 行、改 1 行。

树下面有一行小字：现有的发送函数只是被调用，没有改。

再往下是状态图。一封定时信有五个状态，排队、发送中、已发、失败、已取消，箭头标着怎么从一个状态到另一个，新加的线用虚线。点一个状态，能看到它对应的界面长什么样。

![状态流转图：一封定时信从排队到发送中，再到已发或失败](video_frame_20s.jpg)

评论区的问题他基本都回了。有人问 mockup 是重新画还是复用项目里已有的组件，因为自己的 plan 每次都发明一套新界面，他说复用组件，顺便省 token。

有人问 HTML 会不会比 markdown 费 token，他说用的是组件，和 markdown 差不多。有人嫌界面乱，字号太多，看着不安静，他说这反馈对，设计还要再做。

他自己最喜欢的是调用栈那块，说是从另一个开发者那里学来的，还有能在代码片段上加批注。配图里那段 SQL 的一行旁边就批了一句：两个 worker 不会抢同一条。

他还提了一句，skill 里有一套 lint，专门拦 Claude 做 plan 时常见的翻车，画流程图也在里面。

装法两行命令，放在图下面了。装完 plan mode 本身不会变，要主动说一句用 html-plan 来做。

![配图：调用树和带批注的 SQL](reply_callstacks.jpg)

不管是产品经理还是别的什么人，都是视觉动物，网页和图表传信息的效率本来就比一大段文字高，这点我同意他。plan 写得长，人不会因此更有耐心读它。
