Claude Code 团队的 Addy Osmani 今天发了一篇长文，一天不到 3400 多人收藏，标题是「你的 coding agent 把你变成了经理」。他自己差点合并一个 600 行的改动：测试全绿、命名合理，合并前多看了一眼，加的全是用户用不上的复杂度。他说没有一个经理能讲「那是下属上线的不是我」，agent 也一样。

他把管理的老规矩和 Claude Code 团队这一年的做法对了一遍，我挑了五条：
1. 先给 agent 一个自己能跑的验收（测试 / 构建 / 截图），不然「看起来做完了」就是它仅有的标准，你自己变成它的测试套件
2. 只说它看不到的：会上定的决定、为什么重要、做到什么算完成；代码里有的它自己会读
3. 纠正第二次就写进 CLAUDE.md 或做成 skill；但提示词和 skill 是请求，只有 hook 和 deny 规则是强制，大多数事让模型自己判断，过度流程是新的微观管理
4. 交出任务不交判断：样式、lint、常规 bug 给 agent，安全边界、合规、产品决策留给人，测试绿了就点通过那叫盖章
5. 编排税：每多一个 agent 分走的注意力比上一个多，能扩的是验收不是注意力

我每天四五个 Claude Code 窗口并行，第五条感受最深：一个 agent 跑完弹回来，正在想的念头就丢了。我的五个里只有两个有自己能跑的验收。

他建议睡前开长任务前先答五个问题，可以直接抄：
① 它知道什么算完成吗（目标条件 / 需求文件 / 一个要变绿的失败测试）
② 它有自检吗（测试套件 / Stop hook / 审查步骤）
③ 边界在哪（权限 / 沙箱 / worktree / 只允许推哪条分支）
④ 护栏是什么（轮次上限 / 花费上限）
⑤ 结果交到哪、谁批（PR 或摘要，不可逆操作要人点头）

你现在同时开着几个 agent？哪一个有一条它自己能跑的验收？
